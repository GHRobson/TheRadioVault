# Radio Vault 0.34.0 Alpha 19

Alpha 19 makes the native client's launch sequence reflect the dedicated-server architecture and turns the splash screen into useful startup work.

The previous splash claimed that a local database was being opened and that audio stayed on the client computer. It also disappeared before the Dashboard and Library navigation loaded. Those statements and that sequence were inherited from the former standalone application and were wrong once Radio Vault Server became the archive owner.

The splash now identifies the selected server, whether it is remote or on this computer, and the size and age of the encrypted launch cache. When a paired remote client has cached responses, Radio Vault restores the Dashboard, show navigation, Search, Moments and Queue from disk before constructing and showing the main window. An uncached first launch obtains the same projections from the server and saves them for later launches.

After the desktop opens, the client sends a metadata-only synchronization request using a persistent per-server cursor. If the revision is unchanged, no view is reloaded. If the journal reports a specific kind of change, only the relevant cached projections are refreshed. The server returns no episode collection for this check. A safe full refresh remains the fallback after server restart, journal rollover or a missing older cursor.

Research and transcript operations that currently use authenticated commands rather than cacheable GET projections remain outside the blocking startup path. They still load from the authoritative server when opened.
