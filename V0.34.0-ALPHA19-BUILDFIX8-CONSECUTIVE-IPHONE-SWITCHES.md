# Radio Vault 0.34.0 Alpha 19 Buildfix 8

Buildfix 8 fixes iPhone Safari playback after changing from one broadcast to another. The first broadcast already used the server-positioned representation, but a later switch could briefly reuse the previous broadcast's decoder and then replace it asynchronously with the ordinary full-file stream. Safari could interpret the requested resume point as the end of that stream and stop immediately.

The web player now records the broadcast actually assigned to the audio element. When a tap targets a different broadcast, it opens that broadcast's server-positioned stream synchronously inside the same tap, before transfer and manifest requests begin. The new decoder stays muted while another playback session exists, preserving the single-output handoff boundary, and becomes audible only after the ownership commit succeeds.

Diagnostics now report the audio element's own broadcast identity as well as its canonical base and logical playhead. Regression coverage verifies the consecutive-broadcast branch and verifies that server-positioned audio is materially shorter than the zero-position representation rather than merely carrying a WAV header.

Install the Buildfix 8 server first, then the matching client. Fully close Radio Vault Web on the iPhone, reopen it, and confirm Buildfix 8. Start one broadcast, switch directly to a second, switch back to the first, and then test a native-client-to-phone handoff. Connected capability generation is 30 and the Radio Vault Web shell cache is v54.
