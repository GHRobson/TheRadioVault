# Radio Vault 0.34 Alpha 16 — remote responsiveness and stable playback ownership

Alpha 16 improves the native client when its server is on another computer and makes simultaneous phone/client use unambiguous.

## Faster remote navigation

- Previously, several navigation routes forced a new server load on every click even when the page already held current data.
- Dashboard, Search, Library and Transcripts now reuse their loaded view until an explicit refresh or a relevant change requires new data.
- Common server Library responses are held in a 20-second in-memory cache. Any mutation from this client clears it immediately.
- Search, Moments and Transcripts warm quietly after the Dashboard is visible, reducing first-open waits without delaying startup.
- The existing encrypted disk cache remains the read-only fallback when the server is unreachable.

## Phone and client ownership

- A native client now sends live heartbeats only after the server confirms that client owns playback.
- A passive native client no longer attempts progress writes while Radio Vault Web or another client owns the session.
- Opening both devices does not move playback. Moving playback still requires the centre transport action on the target device.
- The native centre transport button now visibly shows a move-to-this-device arrow when another device owns playback.

## Acceptance check

1. Connect the client to a server on another computer and move repeatedly between Dashboard, Search, Library, Moments and Transcripts.
2. Confirm revisiting loaded tabs is immediate and that the Dashboard appears before background tab warming completes.
3. Start playback on the phone, then leave both Radio Vault Web and the native client open for at least one minute. Confirm ownership does not change by itself.
4. Confirm the native centre play button displays the move arrow while the phone owns playback.
5. Click it once and confirm playback moves transactionally to the client and the phone becomes inactive.
