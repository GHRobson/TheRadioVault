# Radio Vault 0.34.0-rc1-buildfix5

This build repairs iPhone playback when the server-positioned handoff stream cannot be decoded for a particular broadcast.

## Behaviour

- Safari's synchronous playback tap still opens the requested broadcast before any transfer request.
- A positioned stream that does not become ready within 4.5 seconds is treated as a media-source failure, not as a denied user gesture.
- Radio Vault replaces it with the ordinary canonical media source on the same activated audio element, starts that decoder, then seeks and verifies alignment.
- The laptop remains the playback owner unless the iPhone decoder proves that the fallback is ready and aligned.
- Diagnostics now distinguish a failed positioned stream, a successful canonical fallback and an actual Safari permission rejection.

## Verification

- The automated suite checks the fallback ordering and ensures the rejected promise from the replaced stream cannot abort a healthy decoder.
- The Web application cache is v62.
