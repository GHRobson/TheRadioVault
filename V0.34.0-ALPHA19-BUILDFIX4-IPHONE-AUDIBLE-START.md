# Radio Vault 0.34.0 Alpha 19 Buildfix 4

This release fixes iPhone playback initiated directly from the Radio Vault Web Library when no device currently owns playback.

## What the Buildfix 3 diagnostic proved

The canonical MP3 remained healthy: Safari loaded the full 6,263-second duration, entered `playing` and advanced its decoder clock. The transfer then committed successfully and made the iPhone the owner. Safari paused when Radio Vault changed the prepared muted decoder to audible output, and rejected the later `play()` retry because it was no longer inside the original user gesture.

## Gesture-authorized direct playback

When no other output exists, Radio Vault now opens the real canonical media resource and requests audible playback synchronously inside the Library tap. The later manifest and ownership work attaches to that same authorized decoder instead of replacing or reauthorizing it.

The server accepts this audible decoder proof only while playback is genuinely unowned. Laptop-to-phone and other cross-device moves retain the muted target, source-stop receipt and atomic commit rules, preventing overlapping outputs.

## Upgrade and test

Install the Buildfix 4 server first, fully close Radio Vault Web on the iPhone, and reopen it so shell cache v50 is active. With nothing playing elsewhere, start a broadcast directly from the phone Library. Then test a normal laptop-to-phone move separately. Install the matching Buildfix 4 desktop client afterwards.
