# Radio Vault 0.35.0 Alpha 9 Buildfix 1 — Knowledge import apply repair

This buildfix addresses the apply-stage failure reproduced against the paired `GRAHAM-PC` server with `Bennington-All-enriched.trvknowledge`.

## Confirmed cause

- The pack transferred and previewed successfully: 918 records, 1,970 Explore pages, 778 exact archive matches, 140 retained missing recordings and no ambiguous pack matches.
- During authoritative apply, an existing pending reconciliation candidate caused Radio Vault to write `ambiguous` into `research_broadcasts.research_state`.
- `ambiguous` is a reconciliation status, not a valid research state, so SQLite correctly rejected it and rolled back the transaction.

## Repair

- Pending reconciliation decisions retain `needs_review=1` and use the schema-supported `conflicting_information` research state.
- The same correction is applied to authoritative import cleanup, marking a record reviewed and resolving a scalar conflict.
- Apply-stage errors are presented inline with the selected Knowledge database and can be retried.
- The server continues to create and verify a full database safety backup before apply.

## Verification

- A database regression test creates a pending ambiguous reconciliation candidate and proves that review refresh completes without violating the schema.
- The full release gate must pass before installers are produced.
