# Radio Vault 0.34 Alpha 2 — native and Anywhere handoff

Alpha 2 is the first native-client bridge to the dedicated Radio Vault Server. It connects playback ownership only; the remainder of the native application still uses the transitional local service implementations until the Phase 3 contract cutover.

## Acceptance run

1. Start `RadioVault.Server.exe` and leave its settings window open or minimised.
2. Start the matching Alpha 2 native `TheRadioVault.exe`.
3. Play a broadcast in the native client and confirm Radio Vault Anywhere shows the native computer as the active playback device.
4. Move playback to Anywhere and confirm the native decoder stops, the server records its source-stop acknowledgement and Anywhere begins at the protected playhead.
5. In the native client, use the centre player control labelled **Move playback to this device**. Confirm the native decoder prepares silently, aligns, commits ownership and becomes audible only after Anywhere stops.
6. Repeat the transfer in both directions at least three times, including one paused transfer and one transfer after seeking. The canonical broadcast, playhead, speed and play/pause intent must remain stable.

## Safety boundaries

- The server owns the shared playback generation and rejects stale reports.
- The current output remains authoritative until the target decoder reports ready and commits.
- A committed outgoing source pauses before acknowledging that its physical decoder stopped.
- A superseded target remains silent if another transfer wins before it becomes audible.
- Server authentication uses the existing private token and the native loopback client validates the exact Radio Vault server certificate.

## Deferred Phase 3 work

- Native Library, Search, Research, transcription and maintenance reads/writes still require server-client conversion.
- The native Settings view still contains the transitional embedded Anywhere administration service.
- Remote-computer native clients and pairing remain disabled.
