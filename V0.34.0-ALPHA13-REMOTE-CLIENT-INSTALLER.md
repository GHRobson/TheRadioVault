# Radio Vault v0.34.0 Alpha 13 — remote native client and server installer

Alpha 13 completes the first universal native-client pass. The same Radio Vault Client can use the dedicated server on its own computer over loopback or a paired server on another private-network computer over certificate-pinned HTTPS.

## What changed

- Pairing a remote server now selects it automatically for the next launch.
- A remote client checks the saved server immediately and continues monitoring it in the background.
- Healthy connections show live broadcast and show counts.
- Temporary outages use the encrypted response cache read-only and reconnect automatically with bounded retry timing.
- Server identity or certificate failures remain explicit and never cause fallback to an unrelated local database.
- All native Library, playback, queue, Moments, Research, transcript, transcription administration, archive-health and Library-scan services remain routed through the active server contract.
- Radio Vault Server now has a standard Windows installer as well as the portable ZIP.
- The installer uses a per-user location, can start the server at sign-in, creates normal shortcuts and preserves the database, archive settings, transcripts and models during upgrades or uninstall.

## Acceptance

1. On the main archive computer, close the previous server and run the Alpha 13 server Setup executable.
2. Keep **Start Radio Vault Server automatically when I sign in** selected and finish installation.
3. Confirm Server settings opens and the existing Library is still present after starting the server.
4. Enable secure access and remote native clients, then create a pairing code.
5. On another computer, open the Alpha 13 client, find the server and choose **Pair and use server**.
6. Restart the client and confirm Dashboard, Library, Search, playback, Research and transcripts use the main computer's server.
7. Stop the server briefly. Confirm already opened views become cached and read-only, with an automatic retry time.
8. Restart the server and confirm the client returns to live without being paired again.
9. Transfer playback between the main native client, the remote native client and Radio Vault Anywhere in both directions.
10. Run a server-owned transcription or Library scan from the remote client and confirm the work continues if the remote client closes.

Database schema 45, API v1 and capability generation 19 remain unchanged.
