# Radio Vault 0.34.0 Alpha 1

## Purpose

This is the first bounded implementation of the dedicated-server roadmap. It establishes a separately runnable server application and a UI-independent runtime without converting the accepted native application into a client prematurely.

## Server boundary

- `RadioVault.Server.exe` contains only server status and settings.
- `RadioVaultServerRuntime` owns database initialisation, the existing HTTP/PWA server, events and background jobs.
- `HeadlessWebPlaybackController` maintains revisioned playback-session state without opening an audio device.
- The server uses the existing schema-45 database and existing Radio Vault Anywhere identity, token, ports and certificates.
- The server project does not reference the Presentation project and contains no normal Radio Vault feature pages.

## Safety boundary

- Radio Vault 0.33 stable remains separately packaged and recoverable.
- The existing native application remains integrated during Alpha 1.
- Native federation remains disabled.
- Do not run the integrated Anywhere host and dedicated server on the same ports simultaneously.
- Initial validation uses a disposable database and does not alter the live archive.

## Next slice

Add background/tray lifecycle, complete server administration and a loopback health/bootstrap contract. Only then begin routing the native application through the server.
