# Radio Vault 0.34.0-alpha20-buildfix3

This build keeps the laptop's output volume stable when playback moves back from Radio Vault Web.

## Cause

The native client creates a fresh Windows WASAPI output when it takes over playback. Radio Vault previously assigned its internal player level directly to that Windows application audio session. Recreating the output during handoff could therefore replace a quieter level chosen in Windows Volume Mixer with Radio Vault's 80% default.

## Correction

- Radio Vault now applies its player slider as gain within the decoded audio stream.
- The temporary muted preparation used by transactional handoff uses that same internal gain stage.
- The Windows application session and laptop device volume are left untouched.
- Phone and browser volume remain local to those devices.

## Acceptance

1. Set the laptop's Radio Vault level in Windows Volume Mixer to a comfortable value.
2. Play a broadcast in the native client and move it to the phone.
3. Move playback back to the laptop.
4. Confirm the Windows mixer level has not moved and the resumed audio is not unexpectedly louder.
5. Repeat the round trip with a different broadcast.

The full release gate must pass with 236 smoke and regression tests, zero build warnings and zero build errors.
