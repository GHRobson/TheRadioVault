# Radio Vault v0.32.0 Alpha 10 Buildfix 2 — static validation

Build identity: `0.32.0-alpha10-buildfix2-avalonia-xaml-property-fixes`

The second Windows compile reached Avalonia's XAML compiler and exposed two toolkit-specific property errors:

- `LibraryView.axaml` used `Width="Auto"` on a `Border`. Avalonia's `Width` property is numeric; leaving it unset already provides automatic layout.
- `MainWindow.axaml` used WPF's `StrokeLineJoin` property on a `Path`. Avalonia exposes the equivalent as `StrokeJoin`.

Buildfix 2 removes the invalid width assignment and uses `StrokeJoin="Round"`. It also extends source validation across every Avalonia AXAML file to reject numeric layout properties assigned `Auto` and the WPF-only shape properties `StrokeLineJoin`, `StrokeStartLineCap` and `StrokeEndLineCap`. The Buildfix 1 link for `EpisodePresentationService.cs` remains present.

Static checks performed in the packaging environment:

- All XML, XAML, AXAML and JSON files parse successfully.
- No Avalonia AXAML file contains `Width`, `Height`, `MinWidth`, `MaxWidth`, `MinHeight` or `MaxHeight` set to `Auto`.
- No Avalonia AXAML file contains WPF-only shape join/cap property names.
- `MainWindow.axaml` contains `StrokeJoin="Round"`.
- `EpisodePresentationService.cs` remains linked exactly once into the Avalonia project.
- Source-manifest hashes, path safety and ZIP integrity are verified after packaging.

A .NET SDK is unavailable in the packaging environment, so the Windows Release compile must still be confirmed with `BUILD-AND-RUN.cmd`.
