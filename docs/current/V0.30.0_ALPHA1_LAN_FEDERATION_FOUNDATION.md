# Radio Vault v0.30.0 Alpha 1 — LAN Federation Foundation

Version: `0.30.0-alpha1-lan-federation-foundation`

## Purpose

Alpha 1 begins Multi-Device Library Access without changing the canonical database or replacing the local WPF application services. One Radio Vault installation can now advertise itself as the server, another remote client can discover it, the two machines can establish certificate-pinned trust with a short-lived pairing code, and the client can verify an authenticated bootstrap snapshot.

This is the trust and transport foundation for the full remote-client cutover planned for Alpha 2.

## Server

Connected access now has a stable server display name and an optional **Advertise this server library to paired Radio Vault remote clients** setting.

When HTTPS and server federation is active, the server:

- broadcasts a privacy-safe `radiovault-lan-v1` announcement over local multicast;
- exposes no archive token, title, filename, path or personal metadata in discovery;
- creates six-digit pairing codes that expire after five minutes;
- limits a code to ten attempts and consumes it after one successful pairing;
- issues a separate 256-bit token to each remote client;
- accepts remote client tokens in `X-RadioVault-Token` or a Bearer header;
- persists paired clients independently from the Radio Vault Anywhere browser token;
- exposes authenticated federation status and the existing bounded bootstrap contract.

## Remote client foundation

A Radio Vault remote client can:

- listen for servers on the configured discovery port;
- display server name, address, version, pairing readiness and capability generation;
- pair through HTTPS using the temporary code;
- pin the exact discovered server certificate;
- store the server identity and paired-client token locally;
- verify `/api/v1/bootstrap` without placing credentials in a URL;
- report canonical broadcast/show counts and compatibility information;
- forget the saved connection without changing its local library.

Alpha 1 deliberately does **not** switch the main Library, playback, research or settings screens to remote services. That application-service cutover is Alpha 2 work.

## Compatibility

- Database schema: **45**, unchanged.
- Anywhere API version: **v1**, extended compatibly.
- Capability generation: **8**.
- Web-shell generation: **10**, unchanged.
- Secure PWA shell cache: `radio-vault-anywhere-shell-v33`, unchanged.
- IndexedDB: **v2**, unchanged.
- Audio and artwork caches: **v1**, unchanged.

Existing Radio Vault Anywhere clients continue to work without reinstallation or cache migration.
