# Radio Vault 0.42.0 acceptance

This is the release-candidate checklist for the first build in which every
client, server and installer identifies both the same product version and the
exact source commit. A candidate is not promoted merely because it compiles.

## Automated release gate

The complete local or Windows release gate must pass. Its existing focused
runners provide the following acceptance evidence:

| Feature | Required automated evidence |
|---|---|
| Radio Vault Live | A persisted schedule survives a service restart, advances from the server clock, remains identical for all clients and never writes personal progress; duplicate representative episode IDs remain distinct. |
| RSS Archive Inbox | Private credentials remain encrypted, credentials never reach the enclosure host, first-check baselining is respected, conditional requests and content deduplication prevent duplicate downloads, and imported audio is retained if a subscription is removed. |
| Automatic downloads | Wi-Fi policy, new-only watermarks, pause/resume, completed and age cleanup, storage limits, active-playback protection and canonical progress reconciliation all pass in the mobile runner. |
| Collections | Manual order persists after reopening, duplicate names are rejected atomically, stale revisions conflict, smart rules remain live, the Web mutation contract works and the iPhone cache remains readable offline. |
| Release identity | `VERSION.txt` drives desktop, server and iOS assemblies; Apple bundle values match; Windows installer file metadata matches; packaged manifests contain the source commit. |

## Hands-on acceptance

- Install the Windows Server over the preceding build and confirm the existing
  database, archive roots, pairing and RSS subscriptions remain present.
- From iPhone and Mac, open Radio Vault Live at the same time and confirm the
  programme and elapsed time agree. Leave and re-enter Live; ordinary Library
  progress must be unchanged.
- Add a test RSS feed with first-check history disabled. Confirm old items are
  baselined, one newly published item downloads once, appears in Library and is
  not downloaded again after a restart.
- Create a manual collection on one client, add and reorder broadcasts on the
  other, then verify the final order on both. Create a smart collection and
  confirm its contents change when a broadcast is marked listened.
- Enable automatic downloads, verify the Wi-Fi restriction, then take the
  phone offline and play a downloaded broadcast. Reconnect and confirm progress
  reconciles only for that broadcast.
- Open About/Diagnostics on the Mac, Server and iPhone. Record the displayed
  `0.42.0` version and short build identity and compare it with the packaged
  `BUILD_INFO.json` file.
- Complete the iPhone accessibility, audio-output, offline and TestFlight checks
  in [`V0.42.0_IOS_TESTFLIGHT.md`](V0.42.0_IOS_TESTFLIGHT.md).

## Promotion rule

Keep the candidate branch separate from `main` until the automated gate is
green and the affected iPhone, Mac and Windows Server checks above have been
performed. Any fix produces a new candidate build identity and repeats the
affected checks.
