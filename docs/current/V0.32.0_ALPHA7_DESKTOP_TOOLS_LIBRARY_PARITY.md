# Radio Vault v0.32.0 Alpha 7 — Desktop Tools, Library Grid and Now Playing Parity

## Purpose

Alpha 7 moves the Avalonia shell from feature migration into everyday desktop parity. It preserves the accepted Alpha 6 local and Connected Access service graph while restoring high-value WPF presentation behavior and adding the first guarded maintenance workspace.

## Library presentation parity

- The Library now supports List and Grid modes.
- Both modes work in All broadcasts and collection-specific views.
- Per-show views suppress redundant collection text on every card or row.
- The toolbar no longer repeats the selected show or Canonical Library Truth label.
- The compact right-side panel is intentionally information-first: summary, people, topics, progress and listening actions.
- Canonical identity, broadcast UID, collection, media structure and detailed metadata move to a dedicated full Broadcast information page.
- Broadcast information is reachable from each Library row/card context menu and from the compact details panel.

## Now Playing parity

The dedicated Now Playing route presents:

- active artwork, title, show/date identity and multipart state;
- play/pause, seek, skip, speed, volume, favourite, Queue and Moment actions;
- logical whole-broadcast progress;
- summary, hosts, guests, callers, mentioned people, topics and archive/personal notes;
- access to full Broadcast information.

It uses the accepted `PlaybackViewModel`, playback coordinators and local/remote `IBroadcastDetailsService` boundaries rather than duplicating playback state.

## Desktop tools boundary

The Settings & Tools route provides:

- registered Library-folder visibility and guarded registration management;
- archive-health analysis;
- application-data and diagnostic-log access;
- explicit remote-session ownership messaging.

Advanced scan, import, backup, repair and destructive maintenance remain in `TheRadioVault.WpfReference.exe` until the Avalonia parity audit proves cancellation, backup and recovery behavior. Alpha 7 does not proxy or silently downgrade these operations.

## Ownership and compatibility

- Avalonia remains `TheRadioVault.exe`.
- WPF remains `TheRadioVault.WpfReference.exe`.
- Local services operate on the authoritative local database.
- Remote details and metadata remain server-owned and never write through the client local database.
- Database schema remains 45.
- LAN capability generation remains 14.
- API v1 and pairing, certificate and encrypted-cache identities are unchanged.
