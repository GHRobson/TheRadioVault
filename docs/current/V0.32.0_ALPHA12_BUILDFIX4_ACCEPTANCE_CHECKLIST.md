# Alpha 12 Buildfix 4 acceptance checklist

Install the same Buildfix 4 build on the server and laptop. Refresh/reopen Radio Vault Anywhere after the server update so shell cache v34 is active.

## Data safety first

Use a broadcast with a clearly visible saved position well above 10 seconds.

- Start a move to the phone, interrupt networking or force the media preparation to fail before commit. The source must continue playing and saved progress must not move backwards or reset to zero.
- Repeat on the laptop target.
- Retry a failed move. It must resume from the protected current source position, not the beginning.
- Double-tap the move control. Only one preparation may run.
- Interrupt the target immediately after submitting commit, reconnect and retry. The same transfer/generation must be recovered rather than starting over or stopping the target.
- Start a second handoff immediately after the first commits. The first target must remain muted/stop after losing the newer generation.

## Six directions

Test each while the source is playing, then again while paused:

- server → laptop
- laptop → server
- server → phone
- phone → server
- laptop → phone
- phone → laptop

For each direction confirm:

- the source continues until the target has prepared;
- a visible spinner/status appears during preparation;
- ownership changes once;
- the old physical output stops before the target becomes audible, except when the bounded offline-source timeout is intentionally exercised;
- the target starts within roughly one second of the projected source playhead under normal LAN conditions;
- play/pause state and speed are preserved;
- only the owner can seek, skip or alter speed;
- Dashboard, Library and Now Playing show the same live percentage;
- closing and reopening the owner preserves the server-confirmed position.

## Multipart broadcasts

- Transfer while playing part 1, a middle part and the final part.
- Confirm the phone loads the correct canonical part and reports one logical position/duration.
- Allow playback to cross a part boundary on the phone and then transfer to a desktop endpoint.
- Confirm no completion or zero-position write is produced by a short individual part.

## Failure and recovery

- Suspend or disconnect the source immediately after commit. The target may unmute after the bounded safety timeout and must retain ownership.
- Disconnect the target before commit. The source must remain unchanged.
- Disconnect the target after commit. On reconnect, session ownership and durable progress must reconcile without rewinding.
- Leave an old phone PWA tab open during a server update. It must be rejected as a legacy claim path rather than corrupting progress; refresh it to load shell v34.

## Regression checks

- Archive Health works identically on server and remote client.
- Manual and hourly library scans still refresh remote Library/Dashboard/Search.
- Alpha 12 Research Undated and Coverage views still open and import Research packs with visible loading feedback.
- Queue remains visible on an idle Now Playing screen.
