# Radio Vault v0.31.0 final acceptance checklist

Target: `0.31.0`

The directly preceding RC1 already passed the Windows build, complete release gate and live runtime acceptance. Stable acceptance verifies the promoted identity and clean package.

## 1. Build and package

- [ ] Extract the stable source into a new folder rather than merging it with RC1.
- [ ] Build **Release | Any CPU** successfully.
- [ ] Run `RUN-RELEASE-GATE.cmd`; every source, architecture, WPF-independence, build, regression and ProductVersion check passes.
- [ ] Run `package-release.ps1`; the self-contained `win-x64` ZIP, `BUILD_INFO.json` and SHA-256 file are created.
- [ ] Extract the binary ZIP into another clean folder and launch it successfully.
- [ ] Diagnostics/ProductVersion report `0.31.0` and `BUILD_INFO.json` reports the stable channel.

## 2. Existing-install spot-check

- [ ] Open the accepted RC1 local data; no migration or re-adoption is requested.
- [ ] Library counts, settings, progress, favourites, queue, Moments, transcripts and Research remain present.
- [ ] Connect the existing remote client without re-pairing, certificate replacement or cache reset.
- [ ] Play and seek one local broadcast and one remote broadcast; restart and confirm progress.
- [ ] Switch local → remote → local once and close normally without a lingering process.

## 3. Release decision

- [ ] No identity mismatch, packaging failure, data loss, duplicate mutation, shutdown hang or compatibility regression appears.

When these checks pass, v0.31.0 is the accepted Core Hardening stable baseline. Further feature or presentation work belongs in v0.32 rather than a modified v0.31 stable build.
