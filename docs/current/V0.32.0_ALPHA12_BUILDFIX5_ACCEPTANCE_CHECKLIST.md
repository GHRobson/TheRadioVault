# Alpha 12 Buildfix 5 acceptance checklist

Install the same Buildfix 5 package on the desktop server and laptop. Fully close and reopen Radio Vault Anywhere so shell cache v36 is active.

## Baseline playback

- [ ] Starting a local broadcast on the server produces audio promptly without waiting for another device.
- [ ] Starting a broadcast on the laptop begins the remote stream promptly while the Library remains live.
- [ ] Play/Pause becomes usable as soon as the decoder is ready; background ownership publication does not leave a spinner running.
- [ ] Selecting another broadcast does not wait for a handoff transaction unless **Move to this device** was explicitly used.
- [ ] Progress survives pause, application close and relaunch on both machines.

## Connected Access stability

- [ ] Leave the laptop connected for at least 30 minutes; the server indicator remains live unless the server is genuinely unreachable.
- [ ] Exercise Library, Dashboard and Search while audio streams; browsing does not fall into cached mode.
- [ ] A handoff/session request failure does not change Library status to cached.
- [ ] Reconnect restores live mode and reports a meaningful failure reason if it cannot.

## Dashboard

- [ ] The top Dashboard loading bar clears when the overview appears.
- [ ] On This Day topics/details may fill in afterwards without reactivating the global loading bar continuously.

## Diagnostics

On the server and laptop, open Settings → Advanced → Connected playback diagnostics.

- [ ] Enter the same session code on both machines.
- [ ] Run Quick test on each machine.
- [ ] Run Full stress test on each machine.
- [ ] Verify each stage shows Running, Passed, Warning, Failed or Cancelled with a duration.
- [ ] Cancel works during a running test.
- [ ] Copy summary produces readable results.
- [ ] Export creates a `.trvdiag` file on each machine.
- [ ] The selected diagnostic broadcast retains its original listening position and completion state.

## Explicit handoff regression

Only after ordinary playback and connectivity are stable:

- [ ] server → laptop
- [ ] laptop → server
- [ ] server → phone
- [ ] phone → server
- [ ] laptop → phone
- [ ] phone → laptop
- [ ] A failed transfer leaves the original source playing and preserves progress.
