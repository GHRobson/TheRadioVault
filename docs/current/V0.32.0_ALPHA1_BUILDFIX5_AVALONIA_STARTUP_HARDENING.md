# v0.32.0 Alpha 1 Buildfix 5 — Avalonia startup hardening

Build identity: `0.32.0-alpha1-buildfix5-avalonia-startup-hardening`

The Buildfix 4 executable compiled successfully on Windows but could terminate or remain busy before any window became visible. Because the Avalonia project is a `WinExe`, an exception during framework, XAML, database or composition startup produced no console output.

Buildfix 5 changes the startup contract:

- a small code-only startup window becomes the initial desktop main window;
- database initialisation and application-host composition run asynchronously after that window opens;
- the real `MainWindow` replaces the startup window only after composition succeeds;
- a failure keeps the startup window visible and displays the full exception;
- startup checkpoints and exception details are written to `%APPDATA%\TheRadioVault\avalonia-startup-failure.log`;
- failures before Avalonia can create a window use a native Windows error dialog;
- AppDomain, unobserved task and Avalonia UI-thread exceptions are recorded.

No database migration, application-service redesign, LAN/API change, pairing change or cache reset is included.
