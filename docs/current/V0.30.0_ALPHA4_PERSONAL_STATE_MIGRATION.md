# v0.30.0 Alpha 4 — Personal State Migration

Alpha 4 provides a guarded one-time path for consolidating the remote client's personal listening state into the server library before the remote client becomes a pure LAN client.

## Portable package

The remote client exports a `.trvstate` ZIP package containing only portable personal state:

- canonical broadcast identity plus an unambiguous show/date/slot fallback;
- position, duration, completed state and playback speed;
- first played, last played, play count and completion count;
- favourites;
- Moments with timestamp, title, notes and creation time;
- queue order.

The package does not contain audio, filenames, filesystem paths, transcripts, research metadata, access tokens or server certificates. `state.json` is sealed by SHA-256 in `manifest.json`; schema and size limits are checked before preview or import.

## Guarded server import

The server resolves exact canonical keys first, then unique broadcast UIDs, then a unique show/date/slot fallback. Ambiguous or absent identities are reported and not applied.

Before the transaction Radio Vault creates a complete SQLite backup. Merge rules are conservative:

- a completed server broadcast is never replaced by incomplete remote-client progress;
- newer server progress is protected;
- newer remote-client progress may intentionally move backwards, preserving a deliberate recent seek;
- first-played uses the earliest known timestamp and last-played uses the newest;
- play and completion counts use the larger value to avoid double counting overlapping histories;
- favourites are added but never removed;
- equivalent Moments within the existing two-second/title/notes policy are not duplicated;
- the existing server queue keeps its order and missing remote-client items are appended.

A JSON report records source machine, source timestamp, package hash, backup path, applied counts, protected records and unmatched identities.
