# Radio Vault v0.30.0 Alpha 1 Buildfix 1 — LAN Discovery Repair

Version: `0.30.0-alpha1-lan-federation-buildfix1`

## Why this build exists

The first two-PC Alpha 1 test exposed two blockers:

1. neither PC could discover the other Radio Vault server; and
2. the three Connected Access checkboxes returned to their previous checked state after leaving and reopening the page.

## Discovery repair

The original Alpha 1 sender relied on the operating system's single default multicast route. On Windows that route can be a VPN, Hyper-V switch, WSL adapter or other virtual interface rather than the Wi-Fi/Ethernet adapter shared by the two PCs.

Buildfix 1 now:

- enumerates every active private IPv4 adapter;
- sends the privacy-safe `radiovault-lan-v1` announcement over multicast from each adapter;
- also sends the same announcement to each adapter's directed subnet broadcast address;
- joins the multicast group separately on every private IPv4 adapter on the receiving PC;
- continues accepting directed broadcasts on the configured UDP discovery port;
- listens for eight seconds rather than five; and
- reports the adapters and addresses used when no server is found.

No token, archive path, filename, broadcast title or library content is added to discovery traffic.

## Settings persistence repair

The Start Automatically, HTTPS and Server Library checkboxes now save immediately. Enabling server federation automatically enables HTTPS. Disabling HTTPS automatically disables server federation because certificate-pinned pairing cannot operate without it.

If the server is already running, changing one of these options safely restarts the embedded listener with the updated configuration.

- Database schema: **45**
