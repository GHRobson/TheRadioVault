# Radio Vault v0.32.0 Alpha 6 — Connected Access and remote Library parity

Build identity: `0.32.0-alpha6-buildfix1-connected-access-route-import`

## Scope

Alpha 6 makes the Avalonia default desktop a real Connected Access client while preserving the accepted authoritative local-library mode. Startup ownership is selected before database composition: a remote-client launch composes server-backed services and never initialises or writes the dormant local SQLite database.

## Connected Access workspace

The new Avalonia workspace provides:

- LAN server discovery using the existing Radio Vault discovery protocol;
- six-digit desktop pairing with certificate pinning and private client tokens;
- saved-connection testing;
- local/server startup-mode selection and controlled restart;
- live, cached, connecting, updating and unavailable state reporting;
- manual reconnect, automatic reconnect diagnostics and encrypted-cache size;
- explicit removal of the saved server, credentials and server-bound cache.

## Remote Library services

The remote client implements the same presentation contracts used by the local shell:

- `ILibraryBrowseService` for Dashboard, all-broadcasts and per-show Library browsing;
- `ILibraryActionService` for authoritative favourites;
- `ILocalPlaybackLibraryService` for canonical manifests, multipart streaming and progress synchronisation;
- `IQueueService` and `IMomentsService` for server-owned listening state;
- `IResearchWorkspaceService` for normal Research read parity and supported metadata writes;
- `IConnectedAccessService` for ownership and connection lifecycle.

Remote artwork is cached by server identity and broadcast. Remote audio uses the existing loopback credential proxy so certificate and token handling stay inside the Radio Vault process. NAudio receives only loopback HTTP media addresses.

## Live and cached behaviour

`RemoteLibrarySessionCoordinator` owns initial sync, full reset, delta updates, backoff and reconnect. A server/certificate-bound encrypted metadata cache permits read-only Dashboard, Library, Queue, Moments and previously loaded Research browsing when the server is temporarily unavailable. Playback and writes require a live server.

The latest unsent playback position is retained in memory and retried after the session becomes live again. A remote-client mutation never falls through to the local database.

## Research ownership

Normal attached-broadcast metadata can be edited through server API v1. Artwork mutation and advanced Research decisions such as review-state changes remain authoritative-server operations. The client displays those boundaries rather than creating local shadow edits.
