# Radio Vault v0.31.0 Alpha 2 acceptance checklist

Target: `0.31.0-alpha2-application-service-extraction`

## Build and architecture gate

- [ ] Extract to a fresh short local path.
- [ ] Build `Release | Any CPU` in Visual Studio 2022/.NET 8.
- [ ] Run `validate-source.ps1`; source and architecture validation pass.
- [ ] Run `release-gate.ps1`; the regression console suite passes and compiled ProductVersion begins with the target identity.
- [ ] Confirm `artifacts/architecture/architecture-report.json` reports zero violations and architecture version `0.31-alpha2`.

## Startup and library mode

- [ ] Normal local-library startup opens the existing schema-45 library without migration prompts.
- [ ] A saved server-library preference opens in remote-client mode.
- [ ] Launching with `--local-library` overrides the saved server preference for that launch.
- [ ] A stale server-library preference without a saved connection falls back safely to the local library.

## Mode transitions

- [ ] Local → remote opens one replacement window and closes the outgoing window cleanly.
- [ ] Remote → local opens one replacement window and leaves the new window running beyond 12 seconds.
- [ ] Repeated clicks do not create duplicate replacement windows.
- [ ] The local web server remains available after a remote → local transition.

## Shutdown and behaviour preservation

- [ ] Local-mode quit saves progress and exits normally.
- [ ] Remote-mode quit saves server progress when reachable and exits normally when the server is unavailable.
- [ ] No Radio Vault process remains in Task Manager after quitting.
- [ ] Dashboard, Library, Search, playback, queue, favourites, Moments, Research, Transcripts and Connected Access behave as in Alpha 1 Buildfix 2.
