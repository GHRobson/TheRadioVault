# v0.30.0 Beta 1 soak checklist

Target: `0.30.0-beta1-multi-device-hardening`

Use the same build on the server and remote client. Keep the remote client's dormant local archive untouched throughout the pass.

## 1. Build and upgrade

- [ ] `Release | x64` builds without errors.
- [ ] Existing server settings, certificate pin, pairing and remote-client cache are retained.
- [ ] Connected Access reports schema 45 and capability generation 14.
- [ ] Remote-client parity reports every published surface available.

## 2. Incremental synchronization

Start on the remote client with the Library or Dashboard visible.

- [ ] Play one broadcast for at least two minutes while the server remains available.
- [ ] Five-second progress saves update the row/dashboard without a recurring full-window pause.
- [ ] Toggle favourite state and confirm the visible row, Dashboard and filters update.
- [ ] Mark a broadcast played/unplayed and confirm status/progress filters update.
- [ ] Add and remove a queue item and confirm queue order and count update.
- [ ] Edit headline, summary, people and topics in Metadata Studio and confirm the normal Library/search presentation updates.
- [ ] Copy parity diagnostics and confirm the last sync mode becomes `incremental delta` after a mutation.

## 3. Structural synchronization

- [ ] Scan one trustworthy newly added broadcast on the server and confirm it appears remotely after a deterministic full presentation refresh.
- [ ] Restart the server and confirm the remote client enters cached/read-only mode, then returns live after the new server session forces a safe reset.
- [ ] Search, active filters, selected page and playback state remain usable after reconnection.

## 4. Cache and outage behaviour

- [ ] Stop the server while browsing and confirm cached Library, Moments and transcript summaries remain readable.
- [ ] Mutating actions remain clearly blocked while cached/read-only.
- [ ] Restart the server and confirm bounded backoff reconnects automatically.
- [ ] Copy parity diagnostics after one failed poll and verify failure count, next retry and last error are present.
- [ ] A later successful sync clears the last error and resets consecutive failures to zero.

## 5. Playback recovery

- [ ] Stream a normal single-file broadcast remotely.
- [ ] Stream a multipart broadcast through a part transition.
- [ ] Seek, pause, resume, change speed and use skip controls.
- [ ] Interrupt the server briefly and confirm bounded stream recovery resumes near the last observed position.
- [ ] Quit during playback and confirm the final position is preserved without waiting indefinitely.

## 6. Local/remote mode switching

- [ ] From local-library mode, switch to the paired server and leave the replacement remote-client window open for at least 20 seconds. It must not close when the old window’s former 12-second watchdog interval passes.
- [ ] From remote-client mode, switch back to the local library and leave the replacement local window open for at least 20 seconds.
- [ ] Confirm Connected Access on the replacement local window still reports its local web server running; the outgoing remote window must not stop it.
- [ ] Repeat both directions twice and confirm no false unclean-session warning appears and only one Radio Vault main window remains.

## 7. Repeated shutdown pass

Perform at least three exits in each state:

- [ ] idle local-library/server mode;
- [ ] local playback active;
- [ ] idle remote-client live mode;
- [ ] remote playback active;
- [ ] remote client cached/disconnected;
- [ ] remote client reconnecting.

For every exit:

- [ ] the window closes normally;
- [ ] the process disappears from Task Manager within 12 seconds;
- [ ] the next ordinary launch does not report an unclean prior session;
- [ ] listening progress and queue/favourite state remain correct.

If a process is watchdog-terminated, retain `diagnostic.log` and export diagnostics before another long test. The session marker should identify the last shutdown stage reached.

## 8. Daily-driver soak

- [ ] Use the remote client for at least one normal listening session with playback, browsing, search, queue, Metadata Studio and Research.
- [ ] Leave the server/client connected for several hours and verify memory, responsiveness and connection state remain stable.
- [ ] No operation writes to the remote client's dormant local library database.
- [ ] No new feature work is accepted into Beta 1; defects become targeted buildfixes.
