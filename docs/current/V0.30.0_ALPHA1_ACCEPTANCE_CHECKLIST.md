# Radio Vault v0.30.0 Alpha 1 Buildfix 2 Acceptance Checklist

## Build and local regression

- Build the full solution in Visual Studio 2022.
- Launch over the accepted v0.29.0 database and confirm schema 45 opens without migration.
- Confirm Dashboard, Library, playback, favourites, queue, Moments, transcripts, research and Radio Vault Anywhere still work.
- Confirm the installed iPhone shell remains `radio-vault-anywhere-shell-v33` and existing downloads remain available.

## Connected Access persistence

- Toggle **Start connected access automatically with Radio Vault** off, leave the page, return, and confirm it remains off.
- Repeat for HTTPS and server advertising.
- Confirm enabling server advertising automatically enables HTTPS.
- Confirm disabling HTTPS automatically disables authoritative advertising.
- Restore the intended server settings before continuing.

## Server

- Open **Settings → Connected access**.
- Give the server a recognisable name.
- Enable HTTPS and server advertising.
- Start the server and confirm the status reports HTTPS and UDP discovery.
- Create a pairing code and confirm it is six digits, copied to the clipboard and expires after five minutes.
- Confirm discovery traffic reveals no access token or archive content.
- Confirm remote clients are listed without displaying their token.

## Remote client

- On the remote client using the same private network, open **Settings → Connected access**.
- Select **Find Radio Vault servers** and confirm the server appears within eight seconds.
- Confirm the failure message lists the Wi-Fi/Ethernet adapter and local IPv4 address if no server is found.
- Create a fresh pairing code on the server, enter it on the client, then choose **Pair and verify bootstrap**.
- Confirm a valid code is accepted without HTTP 400.
- Confirm an invalid or expired code produces a specific pairing message rather than only a status number.
- Confirm the client reports the server library's canonical broadcast and show counts.
- Restart both applications and run **Test saved connection**.
- Confirm the saved connection uses the same server identity and certificate pin.
- Change or revoke the server's paired credentials and confirm the old client token is rejected.
- Confirm **Forget saved connection** removes only remote trust and does not change the local database or audio.

## Network and failure behaviour

- Stop the server and confirm client discovery/test failure is clear and non-destructive.
- Start it again and confirm the saved connection recovers.
- Try an expired or incorrect pairing code and confirm no credential is issued.
- Confirm ten failed attempts invalidate the active code.
- Confirm a new code works after the previous code has expired or been consumed.
- Confirm Windows Firewall prompts only for private-network access.

Alpha 1 Buildfix 2 is accepted when checkbox persistence, bidirectional discovery between the server and remote client, pairing, token persistence, certificate pinning and authenticated bootstrap verification work without regressing v0.29.0 Anywhere or changing local library data.
