# Radio Vault v0.30.0 RC1 — Multi-Device Release Candidate

Version: `0.30.0-rc1-multi-device-release-candidate`

RC1 is the first v0.30 build intended to prove that Multi-Device Library Access can ship without further feature work. It promotes the accepted Beta 1 application behaviour unchanged and concentrates on build identity, repeatable packaging and final acceptance evidence.

## Retained product behaviour

- One authoritative Radio Vault server and trusted native remote clients on a private LAN.
- Normal application parity for Dashboard, Library, Explore, global search, playback, queue, favourites, listening state, Moments, transcripts, artwork, Broadcast Info, Metadata Studio, Research and mode-aware Settings.
- Encrypted server-bound remote cache with explicit cached/read-only outage behaviour.
- Routine in-place synchronization deltas and deterministic full resets for server-session changes, journal gaps, additions, deletions and show/date moves.
- Safe local-library/remote-client window transitions.
- Two-second bounded final remote progress save and 12-second shutdown watchdog with stage diagnostics.
- Explicit server ownership for repair, rollback, reconciliation and storage operations that must never fall through to a remote client's dormant local database.

## Release-candidate hardening

- The source identity is promoted consistently through `VERSION.txt`, assembly metadata, documentation and regression fixtures.
- The release gate now requests deterministic compilation and verifies the ProductVersion embedded in the built WPF assembly.
- The Windows publish flow writes to a clean `artifacts\publish\win-x64` directory.
- `package-release.ps1` creates a self-contained ZIP, a machine-readable build record and a SHA-256 checksum.
- Final acceptance explicitly covers both an existing Beta 1 installation and a clean RC1 extraction.

## Compatibility boundary

- Database schema: **45**
- LAN capability generation: **14**
- API: **v1**
- Web-shell generation: **10**
- Anywhere shell cache: **v33**
- IndexedDB: **v2**
- Downloaded audio/artwork cache identities: **v1**

No re-adoption, database migration, cache reset, certificate replacement or re-pairing is expected.

## Release-candidate rule

No new major feature should enter RC1. A follow-up build should address only a reproduced defect, a data-safety or privacy issue, a release-blocking performance/accessibility problem, or a packaging/build failure.
