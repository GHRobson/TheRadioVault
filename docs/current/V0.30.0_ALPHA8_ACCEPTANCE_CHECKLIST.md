# Radio Vault v0.30.0 Alpha 8 acceptance checklist

Use the same Alpha 8 build on the server and remote client.

## Build and upgrade

- [ ] `Release | x64` builds with no warnings promoted to errors.
- [ ] The server starts with the existing schema-45 library unchanged.
- [ ] The remote client verifies capability generation 13 and `lan.cache-sync`.
- [ ] Existing favourites, queue, progress, research, Moments and transcripts remain intact.

## First synchronization and cache creation

- [ ] Clear the remote-client cache from Settings, then restart in remote-client mode.
- [ ] Skeleton content appears until the first live Library response is ready.
- [ ] The complete Library, Dashboard and queue match the server.
- [ ] Settings reports a stored cache size and recent synchronization time.
- [ ] No audio files appear under the remote-client cache directory.

## Cached startup

- [ ] Close the remote client after a successful synchronization.
- [ ] Stop the server or disconnect the network.
- [ ] Relaunch the remote client and confirm real cached Library content appears immediately.
- [ ] The connection badge clearly says cached/server unavailable.
- [ ] Library filters and search work against cached data.
- [ ] Cached Moments and transcript summaries remain browseable.
- [ ] The remote client's local-library database is not opened, scanned or changed.

## Read-only safety while unavailable

- [ ] Playback explains that a live server is required.
- [ ] Favourite, listened-state and queue changes are blocked without modifying cached or local data.
- [ ] Moment add/delete and broadcast metadata editing are blocked.
- [ ] Research pack import/export is blocked until reconnection.
- [ ] **Use local library** remains an explicit user action and never occurs automatically.

## Reconnection and incremental synchronization

- [ ] Restart the server and allow the remote client to reconnect automatically.
- [ ] The cached badge changes to live without reopening the application.
- [ ] The current page, filters, search text and selected broadcast remain in place.
- [ ] Add a broadcast on the server and confirm it appears on the remote client without restarting.
- [ ] Delete or remap a test broadcast and confirm the stale cached row disappears.
- [ ] Change favourite, progress, queue, metadata and a Moment on the server; confirm each refreshes remotely.
- [ ] A second remote-client launch uses the updated cache immediately.

## Stream interruption recovery

- [ ] Start a normal server broadcast from the remote client.
- [ ] Interrupt the network briefly while audio is playing.
- [ ] The player shows buffering/reconnecting rather than switching incorrectly to Play.
- [ ] Restore the network and confirm playback resumes close to the last observed position.
- [ ] No duplicate progress or completion state is created.
- [ ] A prolonged failure presents one final useful error after bounded retries.

## Cache controls and identity protection

- [ ] Changing the cache-size setting persists across launches.
- [ ] **Synchronize now** performs an immediate live check.
- [ ] **Clear cached Library** removes the cache but does not forget the paired server.
- [ ] Pairing with a different server never displays the first server's cached Library.
- [ ] Certificate or server identity mismatch causes the cache to be ignored safely.

## Long-session pass

- [ ] Leave the remote client connected for at least two hours.
- [ ] The Library remains live without repeated full reloads or interface resets.
- [ ] Playback state remains correct through pauses, seeks and multipart transitions.
- [ ] Close both applications normally and confirm progress and cache state survive restart.
