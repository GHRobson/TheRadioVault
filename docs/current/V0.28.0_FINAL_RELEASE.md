# Radio Vault v0.28.0 — Final release

## Release boundary

v0.28.0 is a metadata-only promotion of the accepted RC1 implementation, apart from advancing the secure web shell cache identifier so installed mobile clients replace release-candidate HTML. The database schema remains 45 and no canonical archive rows are rewritten by the version change.

## Accepted capabilities

- Canonical Broadcast → Recording → Physical File archive model.
- Guarded Library Truth adoption and permanent audit evidence.
- One canonical library entry for alternate and multipart recordings.
- Continuous multipart playback and assembled transcript/Moment timestamps.
- Crash-safe broadcast-level progress persistence and recovery.
- Idempotent Moment saves/imports and conservative legacy duplicate repair.
- Unified Research & Metadata workspace with rapid decisions and exact navigation.
- Positive Broadcasts to find discovery workflow.
- Archive Health summary with lazy advanced diagnostics and consolidated maintenance.
- Desktop/web ownership transfer, secure local web access and manual offline downloads.

## Final acceptance pass

1. Build the full solution and run `TheRadioVault.Tests`.
2. Open the existing server database and confirm schema 45 with no migration prompt.
3. Play a single-file and multipart broadcast; restart on both sides of a part boundary and confirm progress.
4. Open several Moments and transcript results in later multipart segments.
5. Transfer playback desktop ↔ web and verify position, pause state, recording and speed.
6. Confirm Research and Archive Health open without blocking the interface.
7. Make and undo a rapid metadata decision; verify exact affected-broadcast navigation.
8. Confirm Moments remain deduplicated after restart and rescan.
9. Create a local backup and export diagnostics/Library Truth evidence.
10. Confirm the secure web player refreshes to version 0.28.0 while existing offline audio remains available.

## Rollback

Keep a known-good database backup and the RC1 source until the final build completes its normal-use soak. Because schema remains 45, rollback does not require a reverse migration.
