# Radio Vault v0.31.0 RC1 acceptance checklist

Target: `0.31.0-rc1-core-hardening-release-candidate`

The Beta 1 Windows build, release gate and initial runtime pass are already accepted. RC1 verifies the promoted identity, clean packaging and final daily-driver stability.

## 1. Build and package

- [ ] Extract RC1 into a new folder; do not merge it with a Beta extraction.
- [ ] Build **Release | Any CPU** successfully.
- [ ] Run `RUN-RELEASE-GATE.cmd`; every source, architecture, WPF-independence, build, regression and ProductVersion check passes.
- [ ] Run `package-release.ps1`; the self-contained `win-x64` ZIP, `BUILD_INFO.json` and SHA-256 file are created.
- [ ] Extract the generated binary ZIP into another clean folder and launch it successfully.
- [ ] Diagnostics/ProductVersion report `0.31.0-rc1-core-hardening-release-candidate`.

## 2. Existing-install safety

- [ ] Open the accepted Beta 1 local data with RC1; no migration or re-adoption is requested.
- [ ] Canonical Library counts, folders, settings, progress, favourites, queue, Moments, transcripts and Research remain present.
- [ ] Start the server and connect the existing remote client without re-pairing, certificate replacement or cache reset.
- [ ] Existing cached startup and automatic live reconnect remain functional.

## 3. Local and remote regression

- [ ] Browse Dashboard, Library, Explore, global search, Broadcast Info, Metadata Studio and Research locally.
- [ ] Play single-file and multipart broadcasts; seek, change speed/volume, cross a part boundary and restart to confirm progress.
- [ ] Repeat representative browsing and playback from the remote client.
- [ ] Confirm final remote progress, favourites, listening status, queue and Metadata Studio writes reach the server once.
- [ ] Confirm server-owned storage, repair, reconciliation and rollback operations remain blocked remotely.

## 4. Mode switching and shutdown

- [ ] Switch local → remote → local at least twice, leaving each replacement window open beyond 12 seconds.
- [ ] Exit while idle local, playing local, idle remote, playing remote and reconnecting/synchronising.
- [ ] Each process disappears from Task Manager within the existing watchdog boundary.
- [ ] The next launch shows no false unclean-session warning and preserves progress/state.

## 5. Release decision

- [ ] Complete at least one extended normal listening session on RC1.
- [ ] Leave server and remote client connected for several hours without progressive slowdown or stale state.
- [ ] Export diagnostics and confirm no credentials, tokens or archive audio are included.
- [ ] No data loss, duplicate mutation, stale-cache lockout, indefinite shutdown or unexplained full-Library churn occurs.

When every applicable check passes, promote this exact implementation to `0.31.0` stable. RC2 is reserved for a reproduced release blocker.
