# Radio Vault v0.30.0 Alpha 5 Buildfix 1 acceptance checklist

Use this build on both server and remote client. Start with a normal server backup.

## Build and cutover

- [ ] `Release | x64` builds successfully in Visual Studio 2022 with .NET 8.
- [ ] The server starts normally and reports capability generation 11.
- [ ] Enable remote-client startup on the remote client and restart it.
- [ ] The remote client opens the ordinary Radio Vault `MainWindow`; no alternate remote window appears.
- [ ] Window chrome, sidebar, Dashboard cards, page headers, Library rows and bottom player match local mode exactly.
- [ ] The remote client's real local library counts or broadcasts never flash before the server library loads.

## Normal application surfaces

- [ ] Dashboard counts and Continue Listening match the server.
- [ ] Library show/date/status filters, sorting, search and archive drill-down behave normally.
- [ ] Favourites and bulk listened/unlistened actions write through.
- [ ] Global Search opens results in the usual Radio Vault result list.
- [ ] Moments use the normal Moments page and normal add/edit/delete controls.
- [ ] The Transcripts page lists server transcripts and opens the normal timed transcript viewer.
- [ ] Broadcast Info uses the normal page and its normal metadata editor saves to the server.
- [ ] Settings retains the normal section layout.

## Playback and shared state

- [ ] A single-file broadcast streams through the normal player controls.
- [ ] A multipart broadcast crosses a part boundary without changing UI.
- [ ] Resume, seek, ±30 seconds, speed, pause and completion work normally.
- [ ] Progress survives closing and reopening both applications.
- [ ] Queue add/remove/reorder/clear is shared with the server.
- [ ] Favourite, listened state, Moments and edited metadata appear on the server.

## Ownership and recovery

- [ ] Local storage-maintenance actions explain that they must run on the server.
- [ ] Stopping the server leaves the remote client shell responsive with a useful connection error.
- [ ] `Use this remote client's local library now` opens the same GUI against the untouched remote-client library.
- [ ] A subsequent restart returns to remote-client mode unless the saved default was changed.
- [ ] `--local-library` forces one local launch without forgetting the pairing.

Record any failure with both build versions, the affected broadcast and whether the same action succeeds directly on the server.
