# Radio Vault 0.42 iPhone and TestFlight checklist

This checklist follows Apple's current guidance for
[privacy manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files),
[uploading builds](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/),
[app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)
and [TestFlight testing](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/).

## Before archiving

- Run `./local-release-gate.sh` and retain its validation log.
- Confirm `VERSION.txt`, `ApplicationDisplayVersion` and
  `CFBundleShortVersionString` agree. Increment `ApplicationVersion` and
  `CFBundleVersion` for every App Store Connect upload.
- Confirm the Distribution certificate and App Store provisioning profile use
  bundle identifier `com.ghrobson.theradiovault`.
- Validate `PrivacyInfo.xcprivacy`, the app icon and all usage descriptions in
  the signed archive.
- Put the public privacy-notice URL into App Store Connect and answer the app
  privacy questions consistently with that notice.

## Accessibility and playback acceptance

- At the largest Accessibility text size, open Dashboard, Library, Broadcast
  Info, Explore, Saved, Knowledge, Settings, Radio Vault Live and Now Playing.
  Text must remain readable and actions must remain reachable by scrolling.
- With VoiceOver enabled, traverse each screen in visual order. Every icon-only
  control must announce its purpose and state, and changing Favourite or saving
  a Moment must announce the result once.
- Enable Reduce Motion. The On This Day card must stop auto-advancing and the
  Knowledge decision card must not follow the swipe gesture across the screen.
- From Now Playing and Radio Vault Live, use the output control to select the
  iPhone speaker, Bluetooth headphones and an AirPlay destination. Confirm the
  current output name changes and unplugged headphones pause playback.
- Exercise play, pause, 15-second back, 30-second forward and handoff from the
  Lock Screen, Control Centre, wired/Bluetooth controls and the app.
- Leave the app backgrounded for 30 minutes during streamed and downloaded
  playback, then repeat after an offline cold launch and reconnect.

## TestFlight candidate

1. Archive a Release `ios-arm64` build with automatic App Store signing.
2. Validate and upload the archive through Xcode Organizer or Transporter.
3. Wait for App Store Connect processing, then record the version, build number
   and Radio Vault build identity in the tester notes.
4. Start with an internal group. Test pairing, complete metadata sync, one
   streamed broadcast, one offline download, progress reconciliation, saved
   collections, Live Radio and repeated two-way handoff.
5. Run a 24-hour offline/reconnect soak before inviting external testers.

Apple may require beta-app metadata, export-compliance answers and review for
the first external TestFlight group. Never put certificates, access tokens or
provisioning profiles in the repository or tester notes.
