# Radio Vault v0.32.0 Alpha 2 acceptance checklist

## Build and launch

- [ ] Extract into a fresh local folder.
- [ ] Double-click `BUILD-AND-RUN.cmd`.
- [ ] NuGet restore succeeds.
- [ ] Release build succeeds without errors.
- [ ] The startup window appears immediately.
- [ ] The polished Avalonia `TheRadioVault.exe` replaces the startup window.

## Shell and theme

- [ ] Sidebar identity, navigation and local-library status render cleanly.
- [ ] Dashboard is initially selected.
- [ ] Selecting Library updates the selected navigation state.
- [ ] The application follows the Windows light/dark theme.
- [ ] The bottom playback shell remains visible on both pages.
- [ ] Playback controls are visibly inactive rather than pretending to work.

## Dashboard

- [ ] Totals agree with the accepted WPF reference.
- [ ] Listening completion percentage is sensible.
- [ ] Continue-listening and recently-added rows render correctly.
- [ ] Empty states appear when either collection has no rows.
- [ ] Refresh reloads the current local data.

## Library

- [ ] Search and all listening filters return expected broadcasts.
- [ ] Clear restores all broadcasts.
- [ ] Hover and selected-row states are clear.
- [ ] Favourite and attention states appear where expected.
- [ ] Details update as selection changes.
- [ ] Canonical identity, slot and media structure are correct.
- [ ] A no-results state appears for an impossible search.

## Safety and lifecycle

- [ ] The existing database opens without migration or re-adoption.
- [ ] WPF reference remains available as `TheRadioVault.WpfReference.exe`.
- [ ] Closing Avalonia leaves no Radio Vault process behind.
- [ ] Startup failures, if forced, remain visible and write the startup log.
