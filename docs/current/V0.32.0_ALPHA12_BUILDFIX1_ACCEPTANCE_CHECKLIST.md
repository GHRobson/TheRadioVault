# Radio Vault v0.32.0 Alpha 12 Buildfix 1 — Acceptance checklist

Build identity: `0.32.0-alpha12-buildfix1-handoff-health-library-sync`

## Build and baseline

- [ ] Run `BUILD-AND-RUN.cmd` on the Windows development machine.
- [ ] Confirm the Avalonia Release build succeeds and starts against the existing schema-45 library.
- [ ] Confirm the Alpha 12 queue, Dashboard, artwork, hide-completed, undated and coverage features remain present.

## Shared playback UI

- [ ] Start the server and open Now Playing with nothing loaded; confirm Shared playback is visible.
- [ ] Confirm the server, laptop and active phone/web endpoint appear after each device connects or plays.
- [ ] Confirm the active endpoint is marked ACTIVE and offline/stale endpoints cease to appear online after their lease expires.
- [ ] Confirm Continue on this device appears when another device owns a broadcast.
- [ ] Confirm Move playback to server appears on a connected desktop while that desktop owns playback.

## Moment-to-moment synchronization

- [ ] Play on the desktop server and confirm phone/laptop status follows position and play/pause state.
- [ ] Play on the laptop and confirm server/phone status follows position, speed and play/pause state.
- [ ] Play on the phone and confirm server/laptop status follows the shared playhead.
- [ ] Seek backward and forward on each active endpoint and confirm stale non-owner progress does not overwrite the new position.
- [ ] Repeat with a multipart broadcast and confirm the logical position crosses parts correctly.

## Six handoff directions

- [ ] phone → laptop
- [ ] laptop → phone
- [ ] phone → desktop server
- [ ] desktop server → phone
- [ ] laptop → desktop server
- [ ] desktop server → laptop

For each direction, confirm the previous output pauses, the new output starts from the latest confirmed position, speed transfers, and queue context remains usable.

## Remote Archive Health

- [ ] Analyse Archive Health on the server and note the score/actionable count.
- [ ] Open Settings → Archive on the laptop and confirm the same authoritative report loads rather than Not analysed.
- [ ] Run Analyse archive from the laptop and confirm the server report refreshes.
- [ ] Temporarily disconnect the server and confirm the rest of Settings still opens with a clear health-loading error.

## Library scanning and refresh

- [ ] Add a new supported audio file beneath a registered server root while Radio Vault is open.
- [ ] After the 45-second debounce and scan, confirm the server Library includes it without pressing Refresh.
- [ ] Confirm connected laptop Library, Dashboard and Search update after the server scan revision arrives.
- [ ] Add files while Radio Vault is closed, reopen it, and confirm the hourly due mechanism/initial check discovers them.
- [ ] Press Scan Library now on the server and confirm running/completed status plus counts.
- [ ] Press Scan Library now on the laptop and confirm the scan runs on the authoritative server and the laptop refreshes.
- [ ] Copy a large folder and confirm changes are coalesced rather than starting overlapping scans.

## Regression

- [ ] Confirm local resume persistence and completion behaviour remain correct.
- [ ] Confirm v0.31 server fallback still permits compatible progress writes while hiding unsupported handoff UI.
- [ ] Confirm Radio Vault Anywhere, Research pack import/export and Metadata Studio remain functional.
