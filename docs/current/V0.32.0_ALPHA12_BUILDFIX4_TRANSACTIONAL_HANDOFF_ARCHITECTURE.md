# Transactional handoff architecture

## Purpose

The server owns one canonical playback session shared by three endpoint classes:

- the Avalonia server desktop;
- an Avalonia remote desktop client;
- Radio Vault Anywhere in a browser/PWA.

The transaction exists to guarantee two things simultaneously:

1. a failed target can never stop the working source; and
2. transient decoder state can never replace trustworthy listening progress.

## Authoritative state

The server owns:

- canonical broadcast identity;
- logical multipart position and duration;
- playing/paused state;
- playback speed;
- owner endpoint and monotonically increasing ownership generation;
- one pending transfer ticket;
- the most recent committed source-stop receipt;
- durable listening progress.

Volume and physical output remain local to each endpoint.

## Transfer states

### Idle

No pending ticket exists. Exactly one endpoint is the owner, including while paused.

### Preparing

`Begin` creates a 45-second, single-flight ticket containing the source owner, source generation, source broadcast, protected position, speed and desired play state. No ownership or durable state changes.

### Ready

The target reports that canonical media is loaded and aligned. If playback is active, its decoder must be running muted. The server refreshes the projected source playhead and issues a ready revision. The target may repeat this stage until within alignment tolerance.

### Committed

The server validates the ticket, source generation, ready revision, decoder proof and alignment. It then:

1. writes a monotonic durable progress boundary;
2. increments the ownership generation;
3. installs the target as the sole owner;
4. records a generation-bound source-stop receipt;
5. publishes ownership/session changes.

Begin and commit are idempotent for the exact source/target/broadcast transaction. If a successful HTTP response is lost, the target can retry and recover the existing ticket or committed generation without duplicating ownership changes. Commit is irreversible from the target’s perspective. Later presentation or telemetry failures cannot be reported as a failed transfer.

### Quiescing source

The target remains muted. The outgoing endpoint sees the new generation, physically pauses its decoder and acknowledges the exact transfer ID/source ID/generation. A stale receipt cannot acknowledge a newer move.

### Audible target

The target confirms it still owns the committed generation immediately before unmuting. If a newer move has already superseded it, it stays silent. If the previous source is suspended or offline, a bounded three-second wait permits the valid target to continue without permanent silence.

## Progress channels

### Live session heartbeat

- approximately one second;
- in-memory only;
- generation/owner checked;
- used for projected cross-device playheads;
- never writes listening history.

### Durable progress

- approximately five seconds during healthy playback;
- immediate on pause, explicit seek, completion and shutdown;
- accepted only from the committed owner/generation for rewind-capable writes;
- monotonic unless the current owner explicitly seeks;
- startup-zero and stale decoder positions are rejected.

## Multipart media

All connected targets resolve a canonical media manifest. The logical position maps to one physical part and a part-local seek. Radio Vault Anywhere advances parts while maintaining one canonical logical position and duration. The legacy single-file route is retained only for compatibility/download uses and is not accepted as transactional decoder proof.

## Failure invariants

- Before commit: cancel and leave source/output/progress unchanged.
- Database failure at commit: restore the ticket; source remains owner.
- Source-stop failure after commit: target waits muted, then uses bounded fallback.
- Target status/save failure after commit: keep target active while its generation is still current.
- Newer generation: older source/target outputs stop or remain muted.
- Stale browser/client retry: may advance progress, never rewind it.
