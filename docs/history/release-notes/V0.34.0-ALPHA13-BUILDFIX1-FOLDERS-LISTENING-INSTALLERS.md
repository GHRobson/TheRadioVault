# Radio Vault v0.34.0 Alpha 13 Buildfix 1 — folders, listening state and installers

## What changed

- Radio Vault Server settings now lists the folders registered in the authoritative Library.
- **Add folder** opens a folder picker on the server computer, preventing a remote client from registering a path that exists only on the client.
- Registered folders can be enabled, disabled or safely unregistered without deleting audio files.
- **Scan Library now** runs against the server-owned folder list and reports the result in the settings window.
- The native Library broadcast context menu once again provides **Mark as listened** and **Mark as unlistened**.
- Listening-state changes go through the active server and update canonical broadcast members together.
- Both Radio Vault Client and Radio Vault Server are supplied as normal Windows Setup executables with Start Menu entries and uninstall support.
- Client upgrades retain saved pairing, preferences and encrypted cache. Server upgrades retain the database, archive configuration, transcripts and transcription models.

## Acceptance

1. Exit the old server from its tray icon and run the new server Setup.
2. Open server settings and locate **Library folders**.
3. Add a folder from the server computer, select **Scan Library now**, and confirm broadcasts appear in the clients.
4. Disable and re-enable the folder; confirm its state is clear. Remove a test registration and confirm no audio file is deleted.
5. In the client Library, right-click an unplayed or in-progress broadcast and choose **Mark as listened**.
6. Confirm it displays 100% and appears under Completed.
7. Right-click it again and choose **Mark as unlistened**; confirm progress returns to zero.
8. Install the client through its Setup executable on the laptop and confirm the saved server pairing remains available.

Database schema 45, API v1 and capability generation 19 remain unchanged.
