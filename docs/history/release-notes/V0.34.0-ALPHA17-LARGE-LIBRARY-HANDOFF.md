# Radio Vault 0.34 Alpha 17 — large-library handoff repair

Alpha 17 fixes playback moves to Radio Vault Web that timed out on a server with a large archive.

## Cause

The web browser opened and prepared the requested audio correctly, but the server rebuilt its complete broadcast projection before answering the first transfer request. On a large main library, that work could exceed the browser's 15-second transaction deadline.

## Repair

- Handoff begin now resolves only the requested broadcast directly from the database.
- Canonical broadcasts retain their survivor, multipart, recording, duration and listening-state rules through a canonical-key-filtered query.
- The final commit and outgoing-broadcast preservation use the same direct lookup.
- Ordinary Library pages still use the complete cached projection; only point requests bypass the expensive rebuild.
- Transaction generations, protected positions, ownership checks and source-stop acknowledgement remain unchanged.

## Acceptance check

1. Start a broadcast in the native client connected to the main server and seek well into it.
2. Open Radio Vault Web on a phone or Firefox and choose the move-to-this-device control.
3. Confirm the handoff completes promptly at the same position and audio becomes audible.
4. Move playback back to the native client, then back to Radio Vault Web once more.
5. Confirm only the selected device plays and neither transfer reports a 15-second server timeout.
