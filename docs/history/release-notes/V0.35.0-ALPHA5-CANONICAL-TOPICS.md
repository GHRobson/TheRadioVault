# Radio Vault 0.35.0 Alpha 5 - Canonical topics

Alpha 5 consolidates fragmented topic names before the baseline Wiki is generated.

## Automatic cleanup

- Opening the Wiki runs a safe cleanup pass on Research topics, broadcast tags and Topic Wiki pages.
- Capitalisation, punctuation, spacing and possessive-only differences are merged automatically.
- Every original name remains a searchable alias of the canonical topic.
- New Research edits reuse an established canonical name instead of recreating an alias.

## Reviewed suggestions

- Similar wording is scored using shared normalised topic terms.
- Meaning-based candidates are never silently merged.
- Wiki management includes a Topic cleanup screen with evidence counts, confidence, reasoning and one-click approval.
- The server records automatic and approved merges in durable history.

## Wiki preservation

- The strongest Topic page becomes the canonical page.
- Article text, citations, images, timelines, relationships and aliases are moved to it.
- Older pages are archived and redirected; their IDs and revision history remain available rather than being deleted.
- Radio Vault Web reports topic-cleanup status and can start the safe automatic pass.

## Acceptance checks

1. Upgrade the Server first, then the Client; confirm schema 47 and capability generation 39.
2. Open Wiki management, choose Wiki quality, then Topic cleanup.
3. Confirm punctuation-only duplicates have already consolidated.
4. Review a meaning-based suggestion and verify its archive-reference and Wiki-page counts before merging.
5. Confirm old topic chips and Wiki links open the canonical page.
6. Edit a broadcast using an old alias and confirm the canonical name is stored.
7. Open Radio Vault Web and confirm the canonical-topic status appears on Wiki Home.
