# Radio Vault 0.34 Alpha 14 — Radio Vault Web and phone connection

## Product naming

- The browser and installable PWA companion is now presented as **Radio Vault Web**.
- Existing internal `Anywhere` type, route, storage and cache identifiers remain compatible so the rename does not discard downloads, sessions or handoff state.
- Radio Vault Server remains the background archive owner. Radio Vault Client remains the native desktop interface.

## Phone connection controls

- Server settings contains a dedicated Radio Vault Web card with the private address, an open action, clipboard copy, private-link renewal and locally generated QR codes.
- Client settings receives the private Radio Vault Web and secure-setup addresses through its authenticated paired-server connection.
- Client settings always presents the phone connection controls rather than hiding them behind server-management permissions.
- The main QR opens Radio Vault Web. When HTTPS is enabled, a separate first-time setup QR opens the certificate-trust workflow.
- QR payloads are generated locally. No private server address or access token is sent to an external QR service.

## Security and ownership

- Only an already authenticated native client can request the private Web address from the server API.
- Start, stop, port, certificate and private-link renewal controls remain owned by the server settings app.
- Renewing the Web private link signs existing Web browsers out but does not revoke paired native clients.

## Acceptance

1. Install Alpha 14 Server on the archive computer and Alpha 14 Client on the laptop.
2. Open Server settings and confirm the **Radio Vault Web** card, both QR codes and open/copy controls appear.
3. Open Client settings → **Radio Vault Web** and confirm it identifies the active server and shows the same private address and QR codes.
4. Scan the first-time HTTPS setup QR on a new phone, complete certificate trust, then scan the main Web QR.
5. Confirm the browser/PWA title and visible diagnostic wording say **Radio Vault Web**.
6. Confirm playback and two-way handoff still work from the renamed Web interface.
