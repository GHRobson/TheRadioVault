# Radio Vault 0.34 Alpha 18 — connected-system reliability

Alpha 18 is the feature-free reliability pass for the dedicated server, native clients and Radio Vault Web.

## Playback ownership

- Every explicit native Play gesture is treated as a transactional handoff when another device owns the shared session, even when playback starts from a Library row rather than the centre transport control.
- A non-transactional decoder report can only establish ownership when no other output is active. It cannot steal playback from a phone, browser, server output or another native client.
- Generation checks, protected positions, muted target preparation and physical source-stop receipts remain the ownership boundary.
- A 100-move stress regression rotates playback between phone, laptop, Firefox and server targets.

## Connection and cache recovery

- Retry-safe remote operations use a five-second per-attempt deadline with bounded reconnect attempts. Long-running server mutations and transcription setup keep their existing long operation allowance.
- Cached read-only mode is now represented truthfully in the connection snapshot.
- The independent 15-second health probe invalidates short-lived native memory responses after the server recovers, so the next view refresh reads current server state.
- Dashboard, Search, Library, Moments, Transcripts and Queue reuse recent content immediately, then become eligible for a live refresh after 30 seconds.
- Library show navigation follows the same rule, allowing shows added by another computer to appear without restarting the client.

## Web, parity and upgrades

- Connected capability generation advances to 20.
- Radio Vault Web advances to offline shell v44 so installed phone/browser shells receive this release.
- Client and server installers explicitly retain the previous install directory and task choices and produce setup logs.
- Installer deletion remains restricted to the application binary directory. Pairing, settings, encrypted caches, the database, certificates, transcripts and transcription models remain in separate application-data locations.

## Acceptance check

1. Leave Radio Vault Web and a native client open, then move playback between phone, Firefox and the client several times.
2. Start a different broadcast from a Library row while another device owns playback and confirm it performs one clean handoff rather than overlapping audio.
3. Disconnect the client from the network, confirm cached read-only state appears promptly, reconnect, and confirm live status returns automatically.
4. Add or change content on another device, wait up to 30 seconds, revisit the relevant client view and confirm it refreshes.
5. Upgrade both installers over Alpha17 and confirm pairing, Library folders, database, transcripts, models and startup preference remain intact.
