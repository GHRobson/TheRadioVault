# Radio Vault 0.34.0 RC1

RC1 freezes new features and turns the completed 0.34 client/server architecture into a release candidate. The dedicated Server remains the authority for the Library, playback state, transcription and Radio Vault Web; native and Web applications remain clients.

## RC1 corrections

- A healthy background connection probe no longer discards the native client's warm response cache every 15 seconds.
- A genuine offline-to-live recovery clears stale memory responses once and immediately returns connection state from cached-only to live.
- Every Server start owns immutable HTTP, HTTPS and discovery listener generations, preventing an older cancelled loop from observing a newly restarted listener.
- Existing continuous iPhone playback, repeated handoff and device-local Windows volume fixes remain locked by regression coverage.

## Upgrade preservation

The Client and Server installers retain their stable application identities and previous install/task choices. Installed binaries are replaced, while application data remains outside the installation directories. Upgrading must preserve:

- the authoritative Library database and folder assignments;
- server settings, HTTPS certificates and paired-client trust;
- transcription models, jobs, transcripts and confirmed speakers;
- native-client pairing, preferences and encrypted response cache;
- Research records and Deep Research packs.

## Acceptance pass

1. Upgrade the Server on the main library PC, then upgrade the Client on the laptop.
2. Confirm both retain their settings and the Client reconnects without pairing again.
3. Open Dashboard, Search, Library, Transcripts, Research and Settings; revisit them and confirm warm views remain responsive.
4. Stop and restart the Server while the Client is open. Confirm cached views remain available during the outage and the Client returns to live state automatically.
5. Put the laptop to sleep, wake it and confirm reconnection without losing the selected broadcast or durable progress.
6. Keep a phone and native Client open together and repeat Client to phone to Client to phone handoffs across two broadcasts.
7. Let one phone broadcast play for 20 to 30 minutes without forward skips or backward repeats.
8. Confirm returning playback to the laptop does not change Windows Volume Mixer's Radio Vault level.
9. Add or rescan a Library folder and confirm changes appear in a remote Client.
10. Run a five-minute transcription sample, then pause, resume, cancel and retry jobs.
11. Export and import a Deep Research pack containing a transcript.

Only defects receive RC buildfixes. If this pass succeeds on the library PC, a remote laptop and iPhone, RC1 is eligible for promotion to 0.34 stable.
