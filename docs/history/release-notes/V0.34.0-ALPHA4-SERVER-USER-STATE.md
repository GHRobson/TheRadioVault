# Radio Vault v0.34.0 Alpha 4 — Server-owned user state

Alpha 4 moves the native client’s everyday user-state writes behind the dedicated server. Favourites, durable listening progress, completion state, queue order and Moments now have one authoritative writer shared with Radio Vault Anywhere.

## Acceptance

1. Start the matching Alpha 4 server, then the matching native client.
2. Favourite and unfavourite broadcasts from Library, Search and Now Playing; refresh the page and confirm the state remains correct.
3. Add broadcasts to the queue and Play Next, reorder them, remove one and clear the queue.
4. Create a Moment during playback, edit its title and notes, jump back to it, then delete it.
5. Play a broadcast for at least ten seconds, pause it, restart the native client and confirm it resumes from the saved position.
6. Seek to a clearly different position and confirm the new position survives restart.
7. Move playback to Anywhere and back to the native client, confirming the same position and user state appear on both.

No database migration is performed. The Alpha 4 server and client are a matched pair.

## Remaining transition boundary

Native playback still resolves local media files locally. Research, transcription, archive maintenance, settings and remaining specialist writes continue to use their transitional services until subsequent Phase 3 slices.
