# Radio Vault 0.34.0 Alpha 19 Buildfix 1

This corrective release combines the Alpha 19 cache-first launch work with two repairs found during live client/server testing.

## Transcription save repair

The dedicated transcription worker previously labelled generated transcripts as `server`, while the portable database schema accepts only `local`, `import`, `manual`, or `shared`. Completed speech recognition could therefore fail at the final database write. Generated transcripts now use `local`, which describes work produced by this Radio Vault installation regardless of which process owns the worker. The repository also normalizes unexpected source labels defensively.

Existing failed jobs remain retryable. Select a failed job and use **Retry selected** after installing this build.

## iPhone Safari handoff repair

Diagnostics showed Safari briefly reporting a healthy long MP3 decoder, then changing its duration to the dormant playhead and immediately ending when playback began. The phone no longer repeatedly seeks a paused dormant decoder. The dormant step warms the canonical manifest and media permission at the beginning of the stream; the direct **Move to this device** tap then creates a fresh cache-busted stream, starts it muted within the user gesture, aligns the running decoder, and only commits ownership after the decoder remains ready.

The source device remains authoritative until that proof and the transactional commit succeed.

## Upgrade order

Install the server build first because Radio Vault Web and the transcription worker are hosted by the server. Install the matching client build afterwards. Close and reopen the phone web app once so Safari loads shell cache v47.
