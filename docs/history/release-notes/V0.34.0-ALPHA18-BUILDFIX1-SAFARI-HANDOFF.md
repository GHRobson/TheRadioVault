# Radio Vault 0.34.0 Alpha 18 Buildfix 1

This build fixes the iPhone Safari playback-transfer failure captured on 2 August 2026.

The diagnostic showed that the phone already had broadcast 10389 loaded, ready and aligned within roughly 200 milliseconds of the native client's shared playhead. During the transfer gesture, the web player nevertheless assigned a nearly identical `audio.currentTime`. Safari then reinterpreted the long MP3 range response, changed the media duration from 6,246 seconds to the old 3,203-second playhead, fired `ended`, and correctly failed Radio Vault's target-decoder proof.

The web player now treats a ready decoder within 750 milliseconds of the requested logical position as aligned and does not issue another physical seek. This is the same tolerance required by the transactional commit. Meaningful seeks still use the canonical media-part timeline, and the source device remains authoritative until the target decoder proves readiness and the server commits the transfer.

The corrected shell uses cache v45 and capability generation 21 so an installed phone web app cannot retain the Alpha 18 player code after the server is upgraded.
