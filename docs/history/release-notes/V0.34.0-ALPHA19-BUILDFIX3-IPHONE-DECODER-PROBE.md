# Radio Vault 0.34.0 Alpha 19 Buildfix 3

This release fixes the remaining direct-playback and handoff failure on iPhone Safari.

## What the Buildfix 2 diagnostic proved

Safari reached the canonical recording, reported its real 6,280-second duration and entered `playing`. Six milliseconds later it replaced that resource with a 1-millisecond decoder result and ended. The repeated `seeked` events that followed were against that collapsed resource, not the recording.

## Stream correction

Canonical byte ranges now remain one representation under a shared strong validator. The server no longer emits `Vary: Range`, which incorrectly separated each MP3 range into a different cache representation. It also honors `If-Range`, returns the full representation when a supplied validator is stale, and prevents intermediary content transformation.

## iPhone gesture correction

The dormant iPhone decoder is already warmed at the beginning of the correct recording. The Move tap now starts that same healthy resource muted, proves its clock is advancing, and only then seeks to the protected shared playhead. It no longer replaces the source during the gesture and races Safari's tiny range probe.

If WebKit nevertheless collapses or ends a decoder, Radio Vault stops immediately instead of issuing repeated ineffective seeks. The source device remains the playback owner because the transaction has not committed.

## Upgrade and test

Install the Buildfix 3 server on the library PC first. Fully close Radio Vault Web on the iPhone, reopen it, and confirm version `0.34.0-alpha19-buildfix3`. Test direct playback from the phone Library, then move active playback from the laptop to the phone. Install the matching client build afterwards.
