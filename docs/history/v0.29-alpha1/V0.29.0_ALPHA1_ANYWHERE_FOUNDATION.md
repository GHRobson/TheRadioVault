# Radio Vault v0.29.0 Alpha 1 — Anywhere foundation

Version: `0.29.0-alpha1-anywhere-foundation`  
Database schema: `45`  
Source baseline: accepted Radio Vault `0.28.0`

## Purpose

This alpha establishes the contract that every non-local Radio Vault client will use before it attempts to browse or control an archive. The existing desktop remains the authoritative owner of the database, media and application services.

## Delivered

### Stable server identity

`web-server.json` now retains a GUID instance identity and a human-readable display name. Existing settings are upgraded in place without changing ports, tokens, certificates or downloaded media.

### Capability discovery

`GET /api/v1/server-info` returns:

- authoritative instance ID and display name;
- Radio Vault application version;
- API version and database schema;
- server start/generation timestamps;
- secure-access state;
- explicit read/write/client/planned capabilities.

The response contains no access token, filesystem path, database path or media path.

### First-contact bootstrap

`GET /api/v1/bootstrap?limit=12` provides a bounded lightweight snapshot for web and future desktop clients:

- server information;
- canonical broadcast/show/favourite/continue/completed totals;
- show facets;
- Continue Listening, recent and favourite slices;
- shared playback session;
- shared queue.

This avoids clients guessing supported features or issuing a large burst of unrelated requests at startup.

### PWA connection status

The web shell probes `server-info` rather than treating the player endpoint as a generic health check. While connected, the header identifies the authoritative Radio Vault instance and version. Offline mode remains device-local and continues to expose downloaded broadcasts and pending progress.

## Deliberately unchanged

- Database schema remains 45.
- No Library Truth, metadata, playback, Moment or Research rows are rewritten.
- API v1 remains compatible with the v0.28 web client routes.
- Manual audio/artwork download cache identities remain `audio-v1` and `artwork-v1`.
- LAN discovery and full remote desktop clients are not enabled yet.

## Acceptance pass

1. Build the solution and run all smoke tests.
2. Start the desktop app against the normal schema-45 library.
3. Confirm normal desktop and web playback.
4. Confirm phone downloads from v0.28 remain available.
5. Open the secure web app and verify the server name/version appears when idle.
6. Inspect `/api/v1/server-info` through the tokenised origin and verify schema 45 and the capability list.
7. Inspect `/api/v1/bootstrap?limit=5` and verify bounded library slices, playback and queue.
8. Stop Radio Vault and confirm the web app enters offline mode without losing downloads.
9. Restart Radio Vault and confirm pending offline progress synchronises normally.
