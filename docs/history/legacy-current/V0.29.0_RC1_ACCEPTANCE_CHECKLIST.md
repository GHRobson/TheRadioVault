# Radio Vault v0.29.0 RC1 Acceptance Checklist

Use the real desktop library and the iPhone installation that already contains Beta 2 downloads. Do not clear Safari website data before this pass.

## Upgrade and startup

- Build and launch RC1 over the accepted Beta 2 installation.
- Confirm the server database remains schema 45 and the canonical broadcast count is unchanged.
- Open the existing secure iPhone bookmark and confirm the new shell loads without losing downloaded broadcasts.
- Confirm the update-ready banner can be dismissed and its Reload action returns to the same library state.

## Authoritative and offline use

- Browse several paged Library result sets and exercise show, year, month, date, status and search filters.
- Play a multipart canonical broadcast online, transfer ownership between desktop and iPhone, seek, change speed and resume after restarting both clients.
- Disconnect the server, play at least one downloaded broadcast, change favourite/listening state and queue an item, then reconnect.
- Confirm pending changes apply once, no queue item is duplicated, and progress does not move backwards or reset.
- Run **Check downloads** and repair at least one deliberately missing cache response.

## Moments, transcripts and recovery

- Open a timed transcript, seek from a timestamp and create a Moment at the resulting canonical position.
- Open Anywhere diagnostics, export a report and verify it contains no titles, filenames, paths, tokens or archive text.
- Use **Repair app shell**, reconnect and confirm downloads, local resume positions and pending sync state remain available.

## Accessibility and layout

- On iPhone, confirm Library filters remain collapsed behind the compact Filters control.
- Navigate with an external keyboard: use Skip to content, open and close the sync sheet, Broadcast Info, Now Playing and diagnostics, and confirm focus returns to the invoking control.
- Press Escape to dismiss each open overlay.
- Enable Reduce Motion and confirm the interface remains usable without long animations.

RC1 is accepted when all checks pass without data loss, duplicate mutations, broken downloads, stale-shell lockout, layout obstruction or unrecoverable errors.
