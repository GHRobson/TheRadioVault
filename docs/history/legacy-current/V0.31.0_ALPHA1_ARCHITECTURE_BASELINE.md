# Radio Vault v0.31.0 Alpha 1 — Architecture Baseline

Build identity: `0.31.0-alpha1-architecture-baseline-buildfix1`

## Purpose

Alpha 1 starts Core Hardening without changing Radio Vault's visible behaviour. It records the current coupling, creates a platform-neutral application boundary, establishes explicit UI/platform ports, and makes architectural drift a build-gate failure before any large extraction begins.

## Added boundaries

- `TheRadioVault.Application` targets plain `net8.0` and owns contracts for dispatching, notifications, confirmations, file selection, clipboard access, navigation, window coordination and application lifetime.
- `TheRadioVault.Platform.Windows` is the deliberate Windows/WPF adapter boundary. Its first adapters cover dispatcher access, notifications, file/folder dialogs, clipboard and application shutdown.
- The existing WPF project remains the composition root and references both new projects. No existing workflow has been routed through the new ports yet, so Alpha 1 is behaviour-preserving.

## Enforced rules

`tools/Test-Architecture.ps1` now verifies that:

- Core, Application, Data, Media, Services, Research, Web, Transcription and Tests remain free of WPF/Windows UI dependencies;
- no neutral project references the WPF application or Windows adapter project;
- Application references only Core;
- the Windows adapter boundary cannot reach into databases or feature implementations;
- the WPF composition root references the new application and Windows adapter projects.

The script emits `artifacts/architecture/architecture-report.json` on every validation run. The packaged source also includes `V0.31.0_ALPHA1_ARCHITECTURE_REPORT.json` as the immutable Alpha 1 baseline.

## Baseline coupling inventory

The accepted v0.30 WPF application currently contains 133 C# files, 31 `MainWindow` partial files, 210 `MessageBox` markers, 25 window subclasses, 78 dispatcher markers, 25 open/save dialog markers and 49 `DatabaseService` markers. These are migration measurements, not new defects. They establish the fixed starting point for later alphas.

## Compatibility

- Database schema: **45**
- LAN capability generation: **14**
- API: **v1**
- Web shell/cache identities: unchanged from v0.30.0
- Library adoption, pairing, remote cache and user data: no migration

## Next extraction target

Alpha 2 should move one complete vertical workflow behind the Application contracts—preferably global navigation, notifications and file selection—while preserving the current WPF UI. It should also begin splitting application orchestration out of `MainWindow` and direct database calls out of the desktop project.
