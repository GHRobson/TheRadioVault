# Radio Vault v0.32.0 Alpha 1 Buildfix 2 — Avalonia lifetime alias fix

Build identity: `0.32.0-alpha1-buildfix2-avalonia-default-shell`

## Windows compiler finding

The first Buildfix 1 Windows build found CS0104 because `Avalonia.Controls.ApplicationLifetimes` and `TheRadioVault.Application.Abstractions` both expose a type named `IApplicationLifetime`. The collision affected the Avalonia lifetime adapter and the composition root.

## Correction

Both boundary files now use explicit aliases:

- `AvaloniaDesktopLifetime` identifies Avalonia's `IClassicDesktopStyleApplicationLifetime`.
- `RadioVaultApplicationLifetime` identifies Radio Vault's platform-neutral `IApplicationLifetime`.

The foundation and source validators reject a broad `using Avalonia.Controls.ApplicationLifetimes;` import in those files and require both aliases. This is a compile repair only; it does not change shutdown behaviour or application ownership.

## Compatibility

Avalonia remains the canonical `TheRadioVault.exe`; the retained complete WPF shell remains `TheRadioVault.WpfReference.exe`. Database schema 45, LAN capability generation 14, API v1, pairing, certificates and cache identities are unchanged.
