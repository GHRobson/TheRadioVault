# Radio Vault v0.32.0 Alpha 1 Buildfix 2 acceptance checklist
- [ ] Solution compiles without an ambiguous `IApplicationLifetime` reference; both lifetime boundaries use explicit aliases.

## Clean-source gate

- [ ] Extract into a new local folder.
- [ ] Run `RUN-RELEASE-GATE.cmd`.
- [ ] Source validation passes.
- [ ] architecture validation passes.
- [ ] WPF-independence proof passes.
- [ ] Avalonia-foundation proof passes.
- [ ] Release solution build passes.
- [ ] console regression tests pass.
- [ ] WPF and Avalonia ProductVersion checks pass.

## Avalonia startup

- [ ] Visual Studio selects the shared `Radio Vault (Avalonia default)` launch profile.
- [ ] The Avalonia output is `TheRadioVault.exe`; launching it never opens WPF.
- [ ] Open `TheRadioVault.sln` and press F5/CTRL+F5, or double-click `BUILD-AND-RUN.cmd`.
- [ ] The existing local database opens without migration, re-adoption or repair prompts.
- [ ] `TheRadioVault.exe` opens the Avalonia window and identifies an Alpha 1 local-library session.
- [ ] `avalonia-alpha.log` records `Avalonia application service graph validated`.

## Dashboard vertical slice

- [ ] Broadcast/completed/in-progress/favourite/needs-attention totals appear.
- [ ] Totals are plausible against the accepted WPF application.
- [ ] Continue Listening rows appear where progress exists.
- [ ] Newest Broadcasts are ordered newest first.
- [ ] Refresh completes without a freeze or duplicate rows.

## Library vertical slice

- [ ] Library navigation loads the archive.
- [ ] The source label says `Canonical Library Truth` on the adopted main library.
- [ ] Text search works for a known title, show or date.
- [ ] Continue Listening, Favourites, Completed, Unplayed and Needs Attention filters work.
- [ ] Selecting a row updates the details panel.
- [ ] Progress values stay between 0 and 100 percent.
- [ ] Clear returns to the unfiltered newest-first list.

## Lifecycle and compatibility

- [ ] Repeated Dashboard/Library navigation remains responsive.
- [ ] Closing while loading or idle leaves no Radio Vault process behind.
- [ ] `TheRadioVault.WpfReference.exe` remains available as the explicitly named reference shell.
- [ ] WPF playback, progress and Connected Access still behave normally in a brief spot-check.
- [ ] No database, pairing, certificate or cache reset was needed.

## Alpha 1 boundary

Playback and editing controls are not expected in the Avalonia shell. Their absence is deliberate rather than a failed acceptance item.
