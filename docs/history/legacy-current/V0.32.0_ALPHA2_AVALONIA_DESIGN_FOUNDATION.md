# Radio Vault v0.32.0 Alpha 2 — Avalonia Design Foundation

Build identity: `0.32.0-alpha2-avalonia-design-foundation`

## Purpose

Alpha 1 proved that the new Avalonia executable could open the existing Radio Vault database through hardened application and service boundaries. Alpha 2 deliberately pauses feature migration and establishes the visual foundation that subsequent Avalonia screens will share.

## Delivered design system

- System-aware `Dark` and `Light` theme dictionaries.
- Semantic brushes for background, shell, surfaces, borders, text, accent, success, warning, danger and information states.
- Shared spacing and page-padding resources.
- Reusable styles for navigation, cards, pills, buttons, search fields, filters, Library rows and progress indicators.
- Selected navigation state held by toolkit-neutral presentation view models.
- A persistent bottom playback shell that is visible but inactive until playback migrates in Alpha 3.

## Redesigned vertical slice

### Dashboard

- Archive-ready overview and refresh action.
- Real Library Truth status.
- Listening completion summary.
- Broadcast, completed, in-progress, favourite and attention totals.
- Continue-listening and recent-broadcast sections with explicit empty states.

### Library

- Cohesive search and listening-filter surface.
- Clear result status and Library Truth identity.
- Selected, hover and attention row states.
- Listening progress, favourite state and media structure in the list.
- Structured read-only details with canonical identity and metadata state.
- No-results and no-selection states.

## Startup continuity

The accepted Buildfix 5 startup design remains intact: a visible startup window appears before database/application-host construction; initialization occurs away from the UI thread; failures remain visible and are written to `%APPDATA%\TheRadioVault\avalonia-startup-failure.log`. Alpha 2 restyles that window without weakening its diagnostics.

## Deliberate limits

Alpha 2 remains a local, read-only Avalonia slice. Playback, editing, queue, Moments, Research, Connected Access, settings and specialised workflows remain in `TheRadioVault.WpfReference.exe` while their application boundaries are connected to Avalonia in later alphas.

No database migration, Library Truth re-adoption, LAN capability change, API change, pairing reset or cache reset is introduced. Database schema remains 45 and LAN capability generation remains 14.
