# Radio Vault v0.32.0 Alpha 1 Buildfix 1 — Avalonia default shell

## Purpose

The Alpha 1 foundation already made Avalonia the default in `run-source.ps1`, but the built executable identities still made the WPF shell look canonical. This buildfix removes that ambiguity and makes normal Visual Studio or executable launch open Avalonia without requiring a typed PowerShell command.

## Executable cutover

- `TheRadioVault.Desktop.Avalonia` now builds `TheRadioVault.exe`.
- The retained WPF application now builds `TheRadioVault.WpfReference.exe`.
- Avalonia is first in `TheRadioVault.sln`.
- `TheRadioVault.slnLaunch` contains the shared `Radio Vault (Avalonia default)` profile and starts only the Avalonia project.
- `BUILD-AND-RUN.cmd` and `RUN-RADIO-VAULT.cmd` provide direct double-click build/launch paths using the .NET CLI, not user-entered PowerShell commands.

## Compatibility

There are no database, library, API, LAN, pairing, certificate or cache changes. The Avalonia feature surface remains the Alpha 1 read-only Dashboard and Library vertical slice. The WPF reference remains intentionally available for functionality not yet migrated.

## Superseded for compilation

Buildfix 2 retains this executable cutover and repairs the `IApplicationLifetime` namespace collision found during the first Windows build.
