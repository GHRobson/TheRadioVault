# Radio Vault v0.32.0 Alpha 6 — acceptance checklist

## Build and local regression

- [ ] Extract the path-safe source package into a fresh folder.
- [ ] Double-click `BUILD-AND-RUN.cmd`; package restore, Release build and Avalonia launch succeed.
- [ ] Local-library startup opens the existing schema-45 database without migration or re-adoption.
- [ ] Dashboard, per-show Library, playback, favourites, Queue, Moments, Research and Metadata Studio retain Alpha 5 behaviour.

## Pairing and ownership

- [ ] Connected Access discovers the authoritative Radio Vault server on the LAN.
- [ ] Pairing accepts the server's six-digit code and saves the certificate-pinned connection.
- [ ] Test saved connection reports the expected server name, broadcast count and show count.
- [ ] Selecting the server Library requires a restart and the next launch clearly reports remote ownership.
- [ ] Remote startup does not initialise, migrate or write the client's dormant local database.
- [ ] Selecting the local Library and restarting returns to the existing local archive unchanged.

## Live remote parity

- [ ] Dashboard counts, continue-listening and recent broadcasts come from the server.
- [ ] All-broadcasts and expandable per-show Library navigation match the authoritative server.
- [ ] Artwork loads and is cached without exposing credentials.
- [ ] Remote playback supports play/pause, seek, skip, volume, speed and multipart transitions.
- [ ] Progress and completion persist on the server and appear on another client.
- [ ] Favourites write through to the server.
- [ ] Queue add, play-next, reorder, remove, clear and automatic continuation work remotely.
- [ ] Moments search, create, edit, delete and jump-to-position work remotely.
- [ ] Research overview, browsing, details, sources, diagnostics and import history load from the server.
- [ ] Normal attached-broadcast metadata edits persist through the server API.
- [ ] Protected Research decisions remain visibly server-owned and do not create local edits.

## Cache and reconnect

- [ ] After one live sync, close the server and launch the client again.
- [ ] The encrypted cached Library opens read-only with a clear cached-state indicator.
- [ ] Cached Dashboard, Library, Queue and Moments remain browsable.
- [ ] Playback and write actions explain that a live connection is required.
- [ ] Manual reconnect works after the server returns.
- [ ] Automatic reconnect restores live mode without restarting the client.
- [ ] A progress update interrupted by loss of connection is retried when live mode returns.
- [ ] Forget server removes saved credentials and the server-bound encrypted cache.

## Lifecycle

- [ ] Repeated local/remote restart transitions do not leave duplicate processes.
- [ ] Closing during remote playback attempts final progress synchronisation and exits cleanly.
- [ ] No unhandled UI-thread or background-sync exception appears.

## Buildfix 1 compile gate

- [ ] `TheRadioVault.Desktop.Avalonia` builds without CS0103 for `WebApiRoutes`.
- [ ] The reported nullable warnings in Avalonia shutdown and canonical scan promotion are absent.
