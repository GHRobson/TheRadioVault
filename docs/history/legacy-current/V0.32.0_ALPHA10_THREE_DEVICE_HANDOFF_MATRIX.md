# Alpha 10 three-device playback handoff matrix

Use one authoritative desktop PC server, one paired Avalonia laptop client and one paired iPhone/web client. Use the same multipart broadcast and queue for the main six-direction pass.

## Required directions

| From | To | Required result |
|---|---|---|
| iPhone/web | Avalonia laptop | Laptop shows the phone as active, Continue on this device opens the same broadcast at the latest confirmed logical position and the phone stops owning playback. |
| Avalonia laptop | iPhone/web | Phone takes ownership at the laptop’s latest confirmed position; laptop pauses and displays the phone as active. |
| iPhone/web | Server desktop | Server’s Play here/continue action takes ownership at the current position and the phone pauses. |
| Server desktop | iPhone/web | Phone takes ownership, preserving position and speed, while server audio pauses. |
| Avalonia laptop | Server desktop | Server takes ownership through Move playback to server/Play here and laptop audio pauses. |
| Server desktop | Avalonia laptop | Laptop claims the shared session and starts from the server’s latest confirmed position. |

## Verify for every direction

- Only one endpoint is the active owner after the handoff.
- The broadcast identity is unchanged.
- Logical progress differs by no more than two seconds after startup latency.
- Playback speed transfers; volume does not.
- Play/paused state is intentional and clearly represented.
- The old endpoint does not continue writing competing progress.
- Now Playing identifies the active device on the inactive endpoints.

## Multipart and queue pass

1. Begin in the final minute of part one.
2. Handoff to the second device and cross into part two.
3. Confirm the logical whole-broadcast playhead remains continuous.
4. Add another broadcast to the shared queue.
5. Handoff again before completion.
6. Confirm natural completion advances the same queue once, on the active owner only.

## Stale and offline recovery

- Put the current owner offline without sending a final pause, wait for the playback lease to expire, then claim from another device.
- Reconnect the stale device and confirm it does not steal ownership with an old heartbeat.
- Interrupt the laptop network during progress reporting, reconnect, and confirm pending progress retries without rewinding newer server progress.
- Restart the server and verify all clients recover the canonical session without creating duplicate owners.

## Evidence to capture

Record the direction, source and destination device names, starting/ending logical positions, speed, owner shown on each device, multipart state, queue result and any error or stale-device recovery message.
