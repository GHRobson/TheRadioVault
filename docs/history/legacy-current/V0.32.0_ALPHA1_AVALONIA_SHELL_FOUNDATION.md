# Radio Vault v0.32.0 Alpha 1 — Avalonia Shell Foundation

## Baseline

Alpha 1 starts from the user-accepted v0.31.0 stable Core Hardening source. The WPF application remains present and operational as the reference shell while the replacement desktop is built in bounded vertical slices.

## Delivered architecture

### New desktop shell

`TheRadioVault.Desktop.Avalonia` is a separate .NET 8 executable. It does not reference the WPF application or `TheRadioVault.Platform.Windows`. Its composition root uses the hardened Application registry and verifies the required service graph before freezing registrations.

### Toolkit-neutral presentation

`TheRadioVault.Presentation` contains observable view models, commands and shell navigation. It may use the platform-neutral `System.Windows.Input.ICommand` contract, but it contains no WPF, Avalonia, Windows Registry or direct SQLite/database implementation dependency.

### First read boundary

`ILibraryBrowseService` presents broadcast identity rather than physical files. `LibraryBrowseService` uses adopted canonical Library Truth when the cutover is verified. A read-only legacy fallback keeps a new or unadopted test database usable without mutating or fabricating canonical state.

### Avalonia platform adapters

Alpha 1 supplies adapters for:

- UI dispatcher
- open/save/folder selection
- clipboard
- external URI/file/folder launching
- system appearance
- virtual-screen bounds
- application lifetime
- notifications and confirmations

## Functional vertical slice

The Avalonia shell includes:

- a redesigned navigation shell;
- Dashboard counts for broadcasts, completed, in-progress, favourites and needs-attention items;
- Continue Listening and newest-broadcast lists;
- searchable/filterable Library browsing;
- selection and read-only broadcast details;
- canonical/legacy source indication;
- explicit refresh operations.

## Deliberate Alpha 1 limits

The Avalonia shell does not yet provide playback, queue mutation, favourites mutation, metadata editing, Research, transcripts/Moments, library administration, Connected Access or the specialised WPF windows. Those functions remain available in the accepted WPF reference shell.

No application state is written by the new Dashboard/Library slice.

## Compatibility

- Database schema: **45**
- LAN capability generation: **14**
- API: **v1**
- Web shell generation: **10**
- Existing pairing, certificate and cache identities: unchanged
- Required database migration or re-adoption: none

## Next planned slice

Alpha 2 should introduce an Avalonia-compatible local playback engine behind the accepted playback boundary and connect a minimal Now Playing/playback experience without weakening WPF independence or duplicating persistence policy.
