# Radio Vault v0.31.0 Alpha 5 acceptance checklist

Target: `0.31.0-alpha5-lan-shared-session-consolidation`

## Build and startup

- [ ] Build `Release | Any CPU` from a fresh extraction.
- [ ] Run `validate-source.ps1`.
- [ ] Run `release-gate.ps1`; regression tests pass and compiled ProductVersion begins with the target identity.
- [ ] Local-library startup remains indistinguishable from accepted Alpha 4.
- [ ] Remote-client startup works both with and without an existing encrypted cache.

## Remote session lifecycle

- [ ] A cached Library appears immediately and then updates from the server.
- [ ] A live startup obtains the complete Library and reports a live connection.
- [ ] Routine changes arrive without rebuilding unrelated rows.
- [ ] Repeated refresh/reconnect clicks do not start overlapping synchronizations.
- [ ] Stopping and restarting the server enters cached read-only mode, schedules a retry and returns to live mode.
- [ ] Manual reconnect bypasses the pending retry delay.
- [ ] A client without a usable cache shows the unavailable state and can recover when the server returns.
- [ ] Copied parity diagnostics contain the shared session's last mode, duration, changed rows, failure count, next retry and error.

## Behaviour preservation

- [ ] Remote playback, seeking, progress, favourites, queue, Moments, transcripts, metadata and Research remain functional.
- [ ] Cached mode remains intentionally read-only for server-owned actions.
- [ ] Local → remote → local switching remains safe.
- [ ] Quitting during an active server request completes without hanging and without losing the accepted final-progress behaviour.
- [ ] No re-pairing, cache reset, database migration or Library adoption is requested.
