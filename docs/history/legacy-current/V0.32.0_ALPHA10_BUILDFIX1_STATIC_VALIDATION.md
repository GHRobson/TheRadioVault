# Radio Vault v0.32.0 Alpha 10 Buildfix 1 — static validation

Build identity: `0.32.0-alpha10-buildfix1-episode-presentation-link`

The Windows failure was traced to a project-compilation boundary rather than a missing implementation. `TheRadioVault/Models/Models.cs` is linked into the Avalonia project and calls `TheRadioVault.Services.EpisodePresentationService`, while the helper source was previously compiled only by the retained WPF project.

Buildfix 1 adds an explicit Avalonia linked-source entry for `TheRadioVault/Services/EpisodePresentationService.cs` and a source-package validation guard requiring that link. The helper uses only platform-neutral BCL APIs and implicit .NET usings.

Static checks performed in the packaging environment:

- Avalonia project XML parses and contains exactly one linked compile entry for `EpisodePresentationService.cs`.
- All four failing model references now have their defining source in the same Avalonia compilation.
- The helper has no WPF, Windows-only, database or media dependencies.
- XML/XAML/AXAML and JSON files parse successfully.
- Source-manifest hashes and ZIP integrity are verified after packaging.

A .NET SDK is not available in the packaging environment, so the Windows Release compile still needs to be rerun with `BUILD-AND-RUN.cmd`.
