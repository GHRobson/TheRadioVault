# Radio Vault v0.32.0 Alpha 3 — Local Playback and Rubber-Banding

Build identity: `0.32.0-alpha3-local-playback-rubberbanding`

## Purpose

Alpha 3 is the first Avalonia build intended for normal local listening. It keeps the accepted Alpha 2 shell, startup hardening and read-only Library projection, then connects the new desktop to the hardened playback boundaries created during v0.31 Core Hardening.

## Canonical playback boundary

`ILocalPlaybackLibraryService` resolves a selected canonical broadcast into an ordered `LocalPlaybackDescriptor`. It prefers the verified Library Truth playback plan, selects available preferred physical sources, preserves logical multipart offsets and falls back conservatively to the representative episode's preferred legacy media when canonical cutover data is unavailable.

The service also owns playback-state persistence. Position, duration, completion, speed and play-count evidence are written across members of the same canonical broadcast without exposing SQLite or physical-file identity to the presentation project.

## Avalonia playback engine

`NAudioPlaybackEngine` implements the existing platform-neutral `IPlaybackEngine`. The Avalonia composition root supplies it to `PlaybackSessionCoordinator`; presentation code never constructs or controls WPF `MediaPlayer`.

The persistent bottom bar now provides:

- play and pause;
- 15-second back and 30-second forward;
- direct logical seeking;
- volume;
- playback speed from 0.5× to 3×;
- title, show/date, artwork, position, duration, status and multipart part identity.

Dashboard and Library rows/details expose Play or Resume actions through the shared `PlaybackViewModel`.

## Progress and completion

Alpha 3 reuses `PlaybackProgressCoordinator` and `PlaybackCompletionCoordinator` from the platform-neutral Application layer. Periodic saves reject transient backend zeroes, final shutdown flushes listening state, and completion requires natural forward listening rather than a simple seek to the end.

Multipart broadcasts automatically open the next canonical segment and retain one logical playhead across physical files.

## Global elastic overscroll

Every Avalonia `ScrollViewer` receives the shared `ElasticScroll` attached behaviour from the application style layer. At a vertical edge, wheel input applies a small damped visual displacement and snaps back. The nearest nested viewer owns the response, while normal wheel scrolling, keyboard navigation, Avalonia inertia and scroll chaining remain enabled.

Windows reduced client-area animation preference disables the elastic displacement.

## Preserved boundaries

- Avalonia remains the canonical `TheRadioVault.exe`.
- WPF remains `TheRadioVault.WpfReference.exe` for features not yet migrated.
- Database schema remains 45.
- LAN capability generation remains 14.
- API v1, pairing, certificate and cache identities remain unchanged.
- No library re-adoption or migration is required.
