# Radio Vault v0.31.0 Alpha 4 — Playback and Media Boundary Cleanup

Build identity: `0.31.0-alpha4-playback-media-boundary-cleanup`

## Scope

Alpha 4 preserves the accepted Alpha 3 Windows/platform abstraction while moving the live playback command and persistence-policy path out of WPF presentation code. It deliberately changes ownership boundaries rather than user-visible playback behaviour.

## Application playback session

`PlaybackSessionCoordinator` now owns the active `IPlaybackEngine` for both local-library and remote-client sessions. `MainWindow` supplies the selected platform engine at the composition edge and thereafter uses the session for:

- selecting the active broadcast;
- opening media;
- play, pause, stop and toggle commands;
- seek, skip, speed and volume changes;
- playback status, position, duration and media-path reads;
- media-opened, media-ended, media-failed and state-change notifications;
- final engine disposal during ordered shutdown.

The presentation no longer retains or directly commands a concrete playback engine. LAN-only progress write-through is requested as an adapter capability through the session.

## Progress and completion policy

Two platform-neutral coordinators now own policy that previously lived in `MainWindow.Playback.cs`:

- `PlaybackProgressCoordinator` creates one persistence plan from the reported position, known episode position, player-state position, last observed position and logical resume position. A transient backend zero cannot erase a known positive listening point.
- `PlaybackCompletionCoordinator` tracks natural forward movement and completion evidence. Paused state, deliberate seeks, skips, large jumps and backend corrections cannot count as natural movement into the completion window.

Local database saves, the crash-recovery journal and remote progress synchronisation all consume the same progress plan.

## Windows media adapter

The ordinary WPF `MediaPlayer` implementation has moved from the desktop project into `TheRadioVault.Platform.Windows` as `WpfMediaPlaybackEngine`. The platform-neutral `IPlaybackEngine` contract remains in Core. Certificate-pinned LAN playback continues to implement the same contract and is scheduled for deeper LAN/session consolidation in Alpha 5.

## Architecture gate

The architecture report now records playback-session, playback-progress and completion-coordinator evidence. Validation rejects:

- a WPF-local `PlaybackService` implementation;
- direct `_playback.Play`, `_playback.Pause`, `_playback.Stop`, `_playback.Open`, seek, speed, volume or disposal calls in `MainWindow` partials;
- loss of the Windows media adapter or neutral playback coordinators.
