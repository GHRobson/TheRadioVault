# Radio Vault v0.30.0 Alpha 5 acceptance checklist

> **Superseded:** This checklist belongs to the rejected separate-window Alpha 5 implementation. Use `V0.30.0_ALPHA5_BUILDFIX1_ACCEPTANCE_CHECKLIST.md` for the existing-UI client.


Use the same Alpha 5 build on the server and remote client. Keep a normal Radio Vault backup before testing.

## Build and server

- [ ] `Release | x64` builds successfully in Visual Studio 2022 / .NET 8.
- [ ] `release-gate.ps1` passes.
- [ ] The server starts normally with its canonical library intact.
- [ ] Connected access reports HTTPS and Multi-Device Library Access active.
- [ ] The remote client's saved connection test reports capability generation 11.

## Primary-shell cutover

- [ ] On the remote client, enable **Use the paired server library as this installation's main Radio Vault on startup**.
- [ ] Restart the remote client app; it opens directly into the remote-client shell.
- [ ] The heading identifies the server and the connection is certificate pinned.
- [ ] The remote client's local Dashboard does not briefly open first.
- [ ] Closing the server primary window exits Radio Vault normally.

## Dashboard and Library

- [ ] Dashboard broadcast/show/favourite/continue/completed counts match the server.
- [ ] Continue Listening resumes a known partially played broadcast.
- [ ] Recently Added and On This Day load without freezing.
- [ ] Library search finds a title, person or topic known to exist on the server.
- [ ] Show, year and listening-state filters return the expected bounded results.
- [ ] **Load more broadcasts** appends the next page without duplicating rows.
- [ ] Favourites reflect the server.

## Playback and shared state

- [ ] A single-file broadcast streams and resumes correctly.
- [ ] A multipart broadcast crosses a part boundary on the canonical timeline.
- [ ] Seeking backward and forward writes the deliberate position to the server.
- [ ] Playback speed changes without resetting position.
- [ ] Favourite and listened/unlistened changes appear on the server.
- [ ] Queue add, remove and clear are shared with the server/web app.
- [ ] Closing the shell flushes the current playback position.

## Broadcast information

- [ ] Broadcast Info shows summary, people, topics and archive information.
- [ ] Research status and sources load for a researched broadcast.
- [ ] A Moment can be added at the current position and appears on the server.
- [ ] Double-clicking a Moment seeks to its canonical position.
- [ ] The Moment can be deleted from the client.
- [ ] A transcript loads and double-clicking a segment seeks playback.
- [ ] A broadcast without a transcript reports that cleanly.

## Recovery and preservation

- [ ] With the server stopped, the remote-client shell shows a useful error and remains responsive.
- [ ] **Open local library** opens the remote client's untouched local library for that session only.
- [ ] Restarting still returns to the remote-client shell after the session-only fallback.
- [ ] **Make local library the default** opens local mode and persists it for the next launch.
- [ ] `TheRadioVault.exe --local-library` forces one local launch without forgetting the pairing.
- [ ] Re-enabling remote-client startup does not rescan, merge or change the local archive.
- [ ] Alpha 4 `.trvstate` export/import remains available.

Record any failure with the exact server/remote-client build version, server status, affected broadcast and whether local fallback still worked.
