# v0.30.0 Alpha 1 Buildfix 3 — federation bootstrap verification

## Fault isolated

Buildfix 2 allowed the HTTPS pairing request to complete and save the remote-client credential. The next step then called the full Radio Vault Anywhere bootstrap and the server returned HTTP 500. That proved discovery, certificate pinning, code validation and token issuance had already succeeded; the failure was in the broad dashboard bootstrap used only as a trust check.

## Repair

- A dedicated authenticated `/api/v1/federation/bootstrap` route now returns only server identity, canonical library summary and a bounded queue count.
- The remote client uses this lightweight route for initial verification and **Test saved connection**.
- Playback state, dashboard lists and other phone-only projections are no longer required to prove remote-client trust.
- The full Anywhere bootstrap remains unchanged for the web app, but any failure now returns a structured error code and short diagnostic ID while logging the full exception locally.
- Canonical episode snapshots defensively group duplicate representative IDs before building the lookup dictionary.

## Acceptance

Install Buildfix 3 on the server and remote client. The existing pairing may already be saved on the remote client; first try **Test saved connection**. If it succeeds, the page should display the server's canonical broadcast and show counts without generating another code. If the saved token was removed during testing, create a fresh code and pair again.
