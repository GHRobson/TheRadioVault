# Radio Vault v0.29.0 Final Acceptance Checklist

Use the existing server database and iPhone installation that already passed RC1. Do not clear Safari website data before this pass.

## Build and upgrade

- Build the full solution in `Release | x64` and run `release-gate.ps1`.
- Launch v0.29.0 over RC1 and confirm the existing database opens at schema 45 with unchanged canonical counts.
- Open the existing secure iPhone bookmark and confirm the final shell replaces RC1 without losing downloaded broadcasts, pending changes or local resume state.
- Confirm diagnostics report application version `0.29.0` and shell cache `radio-vault-anywhere-shell-v33`.

## Final regression spot-check

- Browse and search the Library; open and collapse the compact filter panel and load another page of results.
- Play and seek within one single-file and one multipart broadcast, then transfer playback desktop → iPhone → desktop.
- Play a downloaded broadcast with the server unavailable, make one state change, reconnect and verify it synchronises once without moving progress backwards.
- Open a timed transcript, seek from a timestamp and create a Moment at the resulting canonical position.
- Run **Check downloads** and open the synchronisation and diagnostic sheets.
- Use **Repair app shell** only after confirming device media and pending changes are present; verify they remain after reload.
- Restart both desktop and iPhone clients and confirm progress, favourites, queue, Moments and downloaded availability remain intact.

## Acceptance rule

v0.29.0 is accepted when the final metadata promotion builds cleanly, the v33 shell replaces RC1, all RC1 data-safety behaviour remains intact, and no regression, data loss, duplicate mutation, stale-shell lockout or mobile layout obstruction is observed.
