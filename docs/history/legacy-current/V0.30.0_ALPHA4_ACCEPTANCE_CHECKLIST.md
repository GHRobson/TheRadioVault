# v0.30.0 Alpha 4 acceptance checklist

## Build and regression

- [ ] Build `Release | x64` on Windows with Visual Studio 2022.
- [ ] Confirm local Library, normal playback and Alpha 3 remote playback still work.
- [ ] Confirm the remote client can still write progress, favourites and queue changes to the server.

## Personal-state export

- [ ] On the remote client, open Settings → Storage and maintenance → Backups and metadata packages.
- [ ] Select **Export this installation's personal state…** and save a `.trvstate` file.
- [ ] Confirm the summary reports plausible listening-state, Moment and queue counts.
- [ ] Open the package as a ZIP and confirm it contains only `manifest.json` and `state.json`—no audio or filesystem paths.

## Server preview

- [ ] Copy the package to the server and select **Import personal state…**.
- [ ] Confirm the preview identifies matched broadcasts, proposed progress/history merges, favourites, Moments and queue additions.
- [ ] Confirm newer or completed server progress appears under protected state.
- [ ] Confirm unmatched broadcasts are listed and the import can be cancelled without changes.

## Guarded import

- [ ] Apply the import and confirm a backup is created in the Radio Vault Backups directory.
- [ ] Confirm listening progress/history, favourites and Moments appear on the server as expected.
- [ ] Confirm the server queue retains its original order and only missing remote-client items are appended.
- [ ] Confirm duplicate Moments and queue entries are not created.
- [ ] Confirm a JSON report is written in the MigrationReports directory.

## Idempotency and recovery

- [ ] Import the same package a second time and confirm there are no safe changes to apply or no duplicates are added.
- [ ] Confirm the pre-import backup opens/restores through the normal backup workflow if required.
- [ ] Confirm the remote client's audio files and local database remain unchanged.
