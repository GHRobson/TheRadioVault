# Radio Vault v0.29.0 Alpha 2 — Anywhere Web App Cutover

Version: `0.29.0-alpha2-anywhere-web-app-cutover`  
Database schema: `45`

## Purpose

Alpha 1 established the identity, capabilities and bootstrap contract of the Radio Vault server. Alpha 2 makes the secure web companion consume that foundation as its normal application startup and navigation model.

## Delivered

### Bootstrap-driven startup

- One `/api/v1/bootstrap` request supplies server identity, library totals, show/year facets, Continue Listening, recent broadcasts, favourites, On This Day, shared playback and queue.
- Dashboard can render from that bounded snapshot before background polling begins.
- Capability generation advances to 2.

### Canonical Library navigation

- Show, year, month, exact-date and listening-status filters execute on the server.
- Search and date/status facets compose without downloading the complete archive to the browser.
- Every web episode exposes `canonicalBroadcastId` and `identityKind: canonical-broadcast` while retaining `id` for compatibility.
- Cards, Broadcast Info, queue, playback, favourites, listening status, Moments and downloads use that canonical identity.

### Responsive Anywhere shell

- Phone/tablet layout retains the compact sticky header.
- Wide screens use a persistent left navigation rail and a larger content workspace.
- The active primary view, Library view and filters are restored from device-local navigation state.

### Connection and offline boundaries

- The current workspace is no longer silently replaced when the server disappears.
- Server-only navigation is disabled while the existing screen and filters remain preserved.
- Connected content is labelled as the server library; downloaded content is labelled as stored on the current device.
- Reconnection refreshes bootstrap, the active view, shared playback and pending progress without requiring a page reload.

### Browser diagnostics

- A privacy-safe Anywhere Diagnostics panel records bounded startup, slow-request, failure and connectivity events.
- Reports include application/server/API/schema state, current view, download count and playback source.
- Reports omit access tokens, URLs, filesystem paths, titles, summaries, people and topics.

## Safety and compatibility

- Database schema remains 45.
- Audio and artwork caches remain `radio-vault-anywhere-audio-v1` and `radio-vault-anywhere-artwork-v1`.
- Only the secure application shell advances to `radio-vault-anywhere-shell-v27`.
- No archive rows are migrated or rewritten.
- All accepted v0.28 playback recovery, canonical media, Moment deduplication and Research safeguards remain in place.

## Acceptance pass

1. Build the complete solution and run `TheRadioVault.Tests`.
2. Open the web app while connected and confirm the Dashboard appears from the bootstrap snapshot.
3. Exercise show/year/month/date/status/search combinations against the large archive.
4. Play and seek a multipart broadcast, open Broadcast Info and jump to a Moment.
5. Add/remove the broadcast from queue and favourites; confirm the same canonical entry updates.
6. Leave the Library on a filtered date, stop Radio Vault, and confirm the screen/filter state remains preserved.
7. Play a downloaded broadcast offline and save progress.
8. Restart Radio Vault and confirm automatic reconnect, current-view refresh and progress synchronisation.
9. Open Anywhere Diagnostics and confirm the report is useful but contains no token, local path or descriptive archive metadata.
