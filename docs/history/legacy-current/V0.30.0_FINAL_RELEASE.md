# Radio Vault v0.30.0 — Multi-Device Library Access

Version: `0.30.0`

## Release boundary

v0.30.0 is a metadata-only promotion of the successfully built and user-accepted RC1 implementation. It adds no new feature behaviour, API route, LAN capability, database migration, cache identity or pairing requirement.

The release completes the pre-1.0 Multi-Device Library Access milestone: one authoritative Radio Vault instance owns the library and database, while trusted Windows clients use the normal desktop application against that server across a private LAN.

## Completed capabilities

- Privacy-safe LAN discovery, short-lived pairing codes, persistent per-client credentials and certificate-pinned HTTPS.
- Full normal desktop-shell read parity for Dashboard, Library, Explore, global search, Broadcast Info, artwork, transcripts, Moments, Research and Settings diagnostics.
- Server-backed playback, resume progress, favourites, listening state, queue and Metadata Studio editing.
- Explicit server ownership for storage, scans, repair, reconciliation, rollback, Research repair actions and artwork-file changes.
- Encrypted, size-bounded, server-bound remote-client caching with an explicit cached/read-only outage mode.
- Incremental routine synchronization, deterministic full resets for structural changes and detailed parity/synchronization diagnostics.
- Safe switching between local-library and remote-client modes without false shutdown watchdog activation.
- Ordered shutdown, bounded final progress persistence, shutdown-stage evidence and a final 12-second process watchdog.

## Compatibility

- Database schema: **45**.
- LAN capability generation: **14**.
- API: **v1**.
- Web-shell generation: **10**.
- Anywhere shell cache: **radio-vault-anywhere-shell-v33**.
- IndexedDB: **v2**.
- Downloaded audio and artwork caches: **v1**.

Existing accepted RC1 and Beta 1 schema-45 data opens directly. No re-adoption, database migration, cache reset, certificate replacement or re-pairing is expected.

## Release acceptance

Build the stable package in Release configuration, run `release-gate.ps1` and `package-release.ps1`, then complete `V0.30.0_FINAL_ACCEPTANCE_CHECKLIST.md`. Retain the accepted RC1 package and a known-good database backup until the stable build has completed the final spot-check.
