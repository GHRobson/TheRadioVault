# Radio Vault v0.30.0 Alpha 3 — Remote Playback & Write-Through

## Scope

Alpha 2 proved that a remote client can securely browse the server canonical catalogue without touching its own local database. Alpha 3 adds the first interactive application-service cutover while deliberately keeping it inside the native **Server Library** workspace.

## Playback architecture

WPF `MediaPlayer` cannot attach `X-RadioVault-Token` or perform Radio Vault's exact certificate-thumbprint validation. The client therefore starts an ephemeral TCP listener bound only to `127.0.0.1`.

The player opens a loopback URL. The in-process bridge then:

1. accepts only `GET` and `HEAD` requests carrying a random per-session route secret for a canonical episode/media-file pair;
2. validates and parses that loopback path;
3. opens a new certificate-pinned HTTPS request to the paired server;
4. attaches the private remote-client token as a header;
5. forwards byte-range headers and the bounded media response;
6. closes each loopback connection after the response.

The token and certificate thumbprint never enter the playback URL. The bridge listens only while the server playback controller exists and requires no LAN firewall exposure.

## Canonical multipart behaviour

The client loads `/api/v1/broadcasts/{id}/media-manifest`, orders media parts by logical start position, and maps the canonical timeline to the appropriate part. At a natural part ending it opens the next canonical part automatically. Seeking to another part reopens the correct range-capable stream at the corresponding local offset.

## Authoritative writes

The client writes the following directly to the server:

- favourite state;
- listened/unlistened state;
- queue additions, removals and clear;
- listening position, duration, completion and speed.

Offline phone reconciliation remains monotonic. The paired LAN server identifies active playback updates with `AllowRewind`, allowing an intentional backward seek to become the server resume point instead of being mistaken for stale offline progress.

## Connection status

A small title-bar icon appears only when this installation has a saved server:

- green circle and white tick: connected;
- orange circle and rotating arrows: connecting or reconnecting;
- red circle and disconnect mark: unavailable;
- amber circle and warning mark: certificate, identity or authentication attention required.

The icon has accessible text and a tooltip. Clicking it opens **Settings → Connected access**.

## Deliberate limitations

Alpha 3 does not yet replace the normal local Dashboard, Library, Now Playing, Moments or transcript screens. Interactive federation remains in the Server Library workspace so the local application is always available as fallback. Full shell mode selection and feature parity are Alpha 4 work.
