# Radio Vault v0.30.0 Alpha 5 Buildfix 1 — Existing-UI remote client

## Correction

The first Alpha 5 source used a separate `RemoteLibraryWindow`. That was the wrong architecture because the remote client looked and behaved like a companion client rather than Radio Vault itself.

Buildfix 1 removes that presentation layer. Remote-client mode now constructs the normal `MainWindow` and selects remote implementations behind the services already consumed by the WPF shell.

## One shell

The following surfaces are the same XAML, controls, commands and navigation used by a local library:

- Dashboard and Continue Listening
- Library, archive drill-down, filters and sorting
- Global Search and Explore
- Favourites and listening-state actions
- Now Playing, Up Next and the bottom player
- Moments
- Transcripts and timed transcript playback
- Broadcast Info and its metadata editor
- Research workspace
- Settings and Connected Access

No remote-specific top-level window, detail window or Moment editor remains in the source.

## Backing-service selection

At startup, `MainWindow` reads the paired-client preference. Local mode uses the existing SQLite and media services. Remote-client mode uses certificate-pinned LAN implementations for:

- canonical catalogue loading;
- canonical multipart media manifests and byte-range streaming;
- playback progress and deliberate rewind write-through;
- favourites and listened/unlistened state;
- queue reads and mutations;
- Moment reads and mutations;
- transcript lists and transcript documents;
- Broadcast Info metadata updates.

The remote client's real local archive database remains untouched. A separate `remote-client-cache.db` exists only to satisfy framework components that have not yet been fully interface-extracted; it is not populated from or treated as the remote client library.

## Storage ownership

Archive folders, scanning, preservation, backup/restore and other filesystem-owning maintenance still appear in their normal Settings positions. In remote-client mode they explain that the operation must run on the server that owns the archive. This avoids accidentally applying maintenance to the client cache while preserving GUI parity.

## Recovery

`Use this remote client's local library now` reopens the same `MainWindow` with local services. `--local-library` remains a one-launch override. Neither action forgets the pairing unless the user explicitly changes the saved default.

- LAN capability generation: 11
- Anywhere web-shell generation: 10
- Anywhere shell cache: `radio-vault-anywhere-shell-v33`
- IndexedDB: v2
