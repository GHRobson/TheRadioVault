# Radio Vault v0.32.0 Alpha 1 Buildfix 3 — Avalonia namespace and constructor fixes

Build identity: `0.32.0-alpha1-buildfix3-avalonia-default-shell`

## Windows compiler findings

The second Windows build exposed four compile-time issues in the new Avalonia shell:

1. `new AvaloniaStartupOptions(null)` was ambiguous because the positional record also has a generated copy constructor.
2. `Avalonia.Application` was resolved relative to the enclosing `TheRadioVault.Desktop.Avalonia` namespace.
3. `Avalonia.Thickness` was resolved relative to that same project namespace.
4. `Avalonia.Media.TextWrapping` was also resolved relative to the project namespace.

## Corrections

- The default startup option now uses the named argument `DatabasePath: null`.
- Root framework references use `global::Avalonia.Application`, `global::Avalonia.Thickness` and `global::Avalonia.Media.TextWrapping`.
- Source validation now rejects the four ambiguous forms before the Windows compilation stage.

These are compile repairs only. Avalonia remains the canonical `TheRadioVault.exe`; the retained WPF reference remains `TheRadioVault.WpfReference.exe`. Database schema 45, LAN capability generation 14, API v1, pairing, certificates and cache identities are unchanged.
